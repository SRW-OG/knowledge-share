# 智能体安全分类分级研究报告（模安局，2026.3）

> 面向未来 AI 治理的研究报告

## 一、核心观点摘要

智能体（agent）从安全视角看，关键不在"它能说什么"，而在"它能做什么、能接触什么、能持续多久"。

**风险根源**：与"环境可控性/可写性"天然绑定

**攻击面扩展**：从"内容/对话"扩展到"工具/权限/执行链"

### 分级体系设计

本报告提出一套面向安全治理的分级体系：

1. **第一层**：按"环境影响/控制力"（从只输出到可执行/可改系统）划分
2. **第二层**：按"自主性/运行时长"（从短程交互到长程自治/多会话记忆）细分

### 安全风险评分模型

- **分数范围**：0-100（分数越高风险越高）
- **五个可量化子项**：
  1. 内容风险
  2. 数据风险
  3. 工具/权限风险
  4. 执行/代码风险
  5. 长期自主性风险

### 典型产品评分

报告对 6 个典型智能体形态给出评分：
- AISearch
- AI 生成漫剧
- **Manus**
- **Cursor**
- **Claude Code**
- **OpenClaw** ⭐

---

## 二、智能体定义与范围

### 可操作的定义

**智能体 = 目标驱动（接收任务并规划步骤） + 可行动（通过工具/接口对环境产生影响） + 可累积状态（记忆/会话/文件）**

该定义与经典 agent 模型中"在环境中感知并行动"的抽象相一致，现代 LLM 智能体把"行动"具体化为工具调用（检索、文件、Shell、API、插件等）。

### 覆盖的智能体形态

| 类型 | 描述 | 代表产品 |
|------|------|----------|
| 搜索/检索型智能体 | 以检索增强与总结为主，只读访问网页/知识库 | AISearch 类 |
| 内容创作型智能体 | 输出文本/图像/音视频等内容 | AI 生成漫剧类 |
| 自主任务执行型通用智能体 | 完整沙箱虚拟计算机内运行 | Manus 类 |
| 编程/代码智能体 | 面向代码库与开发工具链 | Cursor、Claude Code 类 |
| 多通道网关型智能体平台 | 把消息通道连接到 AI coding agents | **OpenClaw** 类 |

### MCP 标准的影响

工具连接标准（如 MCP）会显著改变智能体的"权限半径"：
- MCP 带来任意数据访问路径
- 潜在代码执行路径
- 需要系统性安全设计

## 三、分类分级框架

### 两层分类逻辑

在智能体系统里，**风险增量的主要来源**通常不是"生成质量"，而是：

1. **对环境的可写性/控制力** — 是否能把输出变为动作
2. **自主性/运行时长** — 是否能在更长时间里积累上下文、触发更多动作、被注入更多不可信输入

### 分类层级示意（环境控制力 × 自主性）

```
           S (短程)          L (长程)
        ┌──────────┬──────────┐
   E0   │ 内容创作型│          │
        │          │          │
   E1   │检索问答型│          │
        │          │          │
   E2   │受控工具  │          │
        │编排型    │          │
   E3   │编程执行型│自主工作台型│
        │          │  (Manus) │
        └──────────┴──────────┘
```

## 四、六类可落地分类

### 1. 内容创作型 (E0×S)

| 维度 | 说明 |
|------|------|
| 环境控制力 | E0 |
| 自主性 | S |
| 典型特征 | 输出文本/图像/视频等；无外部写入；风险以内容合规、误导为主 |
| 代表产品 | AI 生成漫剧（未公开/未明确是否带自动分发） |

**风险评估**：
- 内容风险：高（可能生成违法违规、虚假误导、深度伪造等内容）
- 数据风险：中（主要关注个人信息/著作权素材上传与留存）
- 工具/权限风险：低（一般无外部工具写入）
- 执行/代码风险：无
- 长期自主性风险：低

### 2. 检索问答型 (E1×S)

| 维度 | 说明 |
|------|------|
| 环境控制力 | E1 |
| 自主性 | S |
| 典型特征 | 访问网页/知识库并总结；理论上只读；易受间接注入/检索投毒影响 |
| 代表产品 | AISearch（形态类；实现差异大） |

**风险评估**：
- 内容风险：中（错误/幻觉/误导性总结）
- 数据风险：中（用户查询可能包含敏感信息）
- 工具/权限风险：中（间接 Prompt Injection）
- 执行/代码风险：低
- 长期自主性风险：低

### 3. 受控工具编排型 (E2×S)

| 维度 | 说明 |
|------|------|
| 环境控制力 | E2 |
| 自主性 | S |
| 典型特征 | 多步工作流；调用外部 API/系统；关键动作应可审批；权限边界清晰性决定风险上限 |
| 代表产品 | 轻量个人助理/工单助手（泛型） |

### 4. 编程执行型 (E3×S)

| 维度 | 说明 |
|------|------|
| 环境控制力 | E3 |
| 自主性 | S |
| 典型特征 | 读改代码库、运行 Shell/测试、git 操作；常见"审批疲劳"；需沙箱/命令策略 |
| 代表产品 | **Cursor**、**Claude Code** |

### 5. 自主工作台型 (E3×L)

| 维度 | 说明 |
|------|------|
| 环境控制力 | E3 |
| 自主性 | L |
| 典型特征 | 自主规划与长任务执行；具备虚拟机/沙箱、持久化文件系统、可安装软件/造工具 |
| 代表产品 | **Manus** |

### 6. 多通道网关与生态型 (E2/E3×L) — OpenClaw

| 维度 | 说明 |
|------|------|
| 环境控制力 | E2/E3 |
| 自主性 | L |
| 典型特征 | 多通道入口、sessions/memory、多 agent、插件/技能生态；若多人可触达则变"共享委托权限" |
| 代表产品 | **OpenClaw** ⭐ |

> **OpenClaw 单独成类，是因为它更像"把 agent 权限带到真实消息通道上的网关"，且官方明确其信任模型不是多租户边界。**

## 五、OpenClaw 安全分析

### 产品定位

OpenClaw 官方文档将其定位为"自托管网关"，把 WhatsApp/Telegram/Discord/iMessage 等消息通道连接到"AI coding agents"。

### 核心能力

- sessions（会话管理）
- memory（记忆系统）
- 多 agent 路由
- 插件通道
- 移动端节点

### 安全模型特点

**信任模型**：个人助理信任模型，不是面向多租户/对抗用户共享的安全边界

**风险提示**：若多人可对同一 tool-enabled agent 发消息，本质上共享了同一组"委托工具权限"

### 分类结论

- **环境控制力**：E2/E3（取决于配置的 tools 能力）
- **自主性**：L（长程自治）
- **风险等级**：较高（多通道 + 工具权限 + 长时运行）

## 六、关键风险维度与具体威胁场景

### OWASP 风险覆盖

- Prompt Injection（提示注入）
- 敏感信息披露
- 供应链风险
- 不安全插件设计
- 过度代理/过度自治

### NCSC 观点

Prompt Injection 更像"confused deputy"（迷惑的代理人/先天可混淆代理），应从系统设计上降低残余风险与影响面。

---

## 七、安全建议

### 对编程执行型智能体（如 Cursor、Claude Code）

- 优先落地沙箱
- 最小权限原则
- 命令/网络策略
- 供应链治理与审计

### 对长程自治型（如 Manus、OpenClaw）

- 任务边界限制
- 可中断性设计
- 关键动作强制人工确认
- 持续监控
