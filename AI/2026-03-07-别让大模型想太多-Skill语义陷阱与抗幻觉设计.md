## 一、什么是语义陷阱

**定义**：在人类日常语境中含义相近，但在大模型的语义空间中激活范围（语义边界）存在巨大差异的词汇对。

**本质**：词汇本身固有的语义宽度，能够覆盖并突破 Prompt 所建立的边界控制机制。

---

## 二、"漏洞" vs "风险" 的本质差异

### "漏洞"（Vulnerability）
- 具体的、可被利用的安全缺陷
- **明确的二元判定标准**：存在或不存在
- 有确定的验证方法
- 语义边界**清晰而狭窄**

### "风险"（Risk）
- 代表一种可能性、潜在趋势
- **本质上是程度性问题**（高/中/低）
- 天然携带"展望性"
- 语义边界**模糊而宽泛**

**结果**：大模型在"风险"一词下开始"发散性思考"，输出了定义文件中不存在的风险类型。

## 三、构建高质量 Skill 的四大核心支柱

| 支柱 | 核心作用 | 对抗的问题 |
|------|----------|------------|
| 🏗️ 结构化工作流 | 规定明确的执行路径和顺序 | 防止跳步、乱序执行 |
| ✅ 校验-执行-验证循环 | 外部状态管理 + 强制回读 | 防止遗忘、防止"偷工减料" |
| 📋 定义文件 + 判定示例 | 穷举式边界定义 | 防止自由发挥、越界判断 |
| 🔧 领域定制工具 | 收窄操作空间 | 防止无效探索、错误操作 |

### 1. 结构化工作流
将任务拆解为有序的、具有依赖关系的步骤序列：
```
STEP 1: Progress 文件创建
STEP 2: 链路追踪分析
STEP 3: 参数流向分析
STEP 4: 接口分析
STEP 5: 漏洞评估判定
STEP 6: 生成 Final Answer
```

### 2. 校验-执行-验证循环
- **阶段 1 — 前置校验**：读取进度文件，确认上一步已完成
- **阶段 2 — 执行过程**：执行命令，记录结果
- **阶段 3 — 后置校验**：回读进度文件，验证结论

**关键**：强制大模型"回头审视"已有的工作成果

### 3. 定义文件
- 穷举式精确定义"什么构成漏洞、什么不构成漏洞"
- 包含"无漏洞场景"的具体代码模式
- 预先识别常见误判情况
- 提供 Few-shot 判定示例

### 4. 领域定制工具
- 通用型 MCP 工具无法告诉大模型"什么时候该用、为什么要用"
- 领域定制工具明确定义每个命令的使用时机
- 搜索结果按审计优先级智能排序

## 四、常见语义陷阱词汇对

| 窄边界词（推荐） | 宽边界词（谨慎） | 典型失控场景 |
|------------------|------------------|---------------|
| 检查 (Check) | 审查 (Review) | "审查"触发主观评价 |
| 列出 (List) | 描述 (Describe) | "描述"触发解释和评论 |
| 缺陷 (Defect) | 问题 (Issue) | "问题"范围过于宽泛 |
| 总结 (Summarize) | 分析 (Analyze) | "分析"触发推理和假设 |
| 要求 (Requirement) | 建议 (Suggestion) | "建议"触发发散思维 |
| 错误 (Error) | 异常 (Anomaly) | "异常"边界定义模糊 |

## 六、实战避坑指南

### 1. 词汇选择原则
- 使用**名词**代替形容词化的描述
- 使用**动宾结构**代替开放式动词
- 预先测试"同义词"的语义宽度

### 2. 语义漂移测试
- **排除测试**：询问"还有什么也属于 X 的范畴？"
- **最小对比测试**：换词对照实验
- **边界锚定策略**：
  - 前置否定清单
  - 输出格式硬约束（填空题而非作文题）
  - 判定示例的反例强化

### 3. Skill 自检清单
- [ ] 核心术语是否选择语义边界最窄的词？
- [ ] 是否包含明确的"不包括"排除列表？
- [ ] Final Answer 是"填空题"还是"作文题"？
- [ ] 判定示例是否包含反例？
- [ ] 是否设计了外部状态文件？
- [ ] 工具是否具备足够的领域化程度？
