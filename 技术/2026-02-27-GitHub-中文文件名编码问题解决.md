# GitHub 中文文件名显示八进制转义问题解决

## 问题描述

在 GitHub 网页上，中文文件夹名和文件名显示为八进制转义序列，例如：
- `AI工具` 显示为 `\345\267\245\345\205\267`
- `技术` 显示为 `\346\212\200\346\234\257`

## 原因分析

Git 默认会对非 ASCII 字符（如中文、日文等）进行转义，将其显示为八进制转义序列。这是因为 Git 的 `core.quotepath` 配置默认为 `true`。

当在 `core.quotepath=true` 的情况下执行 `git add` 时，Git 会把转义后的八进制字符串作为文件名写入到 Git 索引（index）中。一旦索引中记录了错误编码的文件名，推送到 GitHub 后就会显示为八进制转义序列。

## 核心解决步骤

### 1. 配置 Git 关闭路径转义

```bash
git config --global core.quotepath false
```

**注意**：这条命令需要在 `git add` 之前执行，否则无效。

### 2. 清除当前索引缓存

由于文件名已经在索引中"损坏"，需要把它们从索引中删除，重新添加：

```bash
git rm -r --cached .
```

**注意**：这只会从索引中删除文件，不会删除物理文件。

### 3. 重新添加文件

此时 Git 会按照 `quotepath=false` 的新规则，正确识别中文编码：

```bash
git add .
```

### 4. 提交并推送

```bash
git commit -m "Fix Chinese filename encoding"
git push
```

## 完整操作流程示例

```bash
# 1. 确保配置已生效
git config --global core.quotepath false

# 2. 进入仓库目录
cd ~/Documents/Obsidian/knowledge-share

# 3. 清除索引缓存
git rm -r --cached .

# 4. 重新添加文件
git add .

# 5. 提交
git commit -m "Fix Chinese filename encoding"

# 6. 推送（可能需要强制推送覆盖远程）
git push -f origin main
```

## 常见问题

### Q: 为什么 GitHub 网页还是显示乱码？

A: 请强制刷新浏览器（Ctrl+F5 或 Cmd+Shift+R）。也可能是 GitHub 网页缓存，API 返回值已经正确。

### Q: 需要使用 GitHub API 来创建中文文件夹吗？

A: 不需要。只要在 `git add` 之前正确配置了 `core.quotepath=false`，GitHub 会自动正确显示中文。

### Q: 这个配置是全局的吗？

A: 使用 `--global` 参数是全局配置，对所有仓库生效。也可以只对当前仓库配置，去掉 `--global` 参数即可。

### Q: 如何验证配置是否生效？

A. 执行以下命令检查：

```bash
git config core.quotepath
# 应该输出 false
```

查看 `git status` 时，如果显示正常的中文而不是八进制转义，说明配置生效。

## 预防措施

1. **新仓库初始化后立即配置**：

```bash
git init
git config core.quotepath false
```

2. **在 `.gitconfig` 中添加全局配置**：

```bash
git config --global core.quotepath false
```

3. **在脚本中添加配置**：如果使用自动化脚本同步文件，确保在 `git add` 之前执行配置命令。

## 总结

- `core.quotepath false` 不仅仅是解决本地终端显示问题，它直接影响 `git add` 时 Git 如何处理和存储文件名
- 关键是要在文件被添加到索引**之前**配置该选项
- 如果已经添加了错误编码的文件，需要清除缓存后重新添加
- 不需要使用 GitHub API 特殊处理，GitHub 的显示完全取决于推送的 Tree Object
