# 本地化 AI 记忆系统架构与部署指南

## 1. 问题现状

### 背景描述

在 AI Agent 系统中，如何让 AI 具备持久记忆能力是一个核心挑战。传统方案依赖云端 API（如 OpenAI）实现语义搜索，但存在以下问题：

- **成本问题**：OpenAI API 按 token 收费，大量记忆检索成本高昂
- **隐私风险**：记忆数据需上传至第三方云服务，存在敏感信息泄露风险
- **网络依赖**：无法离线工作，网络不稳定时服务不可用
- **定制受限**：无法根据特定场景选择或微调 embedding 模型

### 风险评估

| 风险类型 | 级别 | 说明 |
|----------|------|------|
| 数据泄露 | 高 | 敏感记忆数据上传云端 |
| 服务中断 | 中 | 过度依赖外部 API |
| 成本失控 | 中 | 大规模使用 token 费用 |
| 隐私合规 | 高 | 不满足本地化部署要求 |

### 影响范围

- 个人 AI 助手（OpenClaw）
- 企业内部 AI 系统
- 需要私有化部署的安全敏感场景
- 离线环境下的 AI 应用

---

## 2. 解决思路与方案对比

### 方案一：完全云端方案（OpenAI API）

使用 OpenAI 的 Embedding API + 云端向量数据库。

| 优点 | 缺点 |
|------|------|
| 部署简单 | 费用高昂 |
| 模型成熟 | 隐私风险 |
| 维护简单 | 网络依赖 |

### 方案二：混合部署（部分本地）

本地部署向量数据库，但使用云端 Embedding API。

| 优点 | 缺点 |
|------|------|
| 数据本地存储 | 仍依赖云端 API |
| 降低部分成本 | 隐私问题未完全解决 |

### 方案三：完全本地化部署（推荐）

使用 Ollama 或本地模型生成 Embedding，本地向量数据库存储。

| 优点 | 缺点 |
|------|------|
| 零 API 费用 | 首次部署复杂 |
| 完全隐私 | 需要硬件资源 |
| 离线可用 | 模型更新需手动 |
| 可定制模型 | 维护成本 |

### 方案对比表

| 维度 | 云端方案 | 混合方案 | 完全本地 |
|------|----------|----------|----------|
| **费用** | $0.0004/1K tokens | 中 | 免费 |
| **延迟** | ~100ms | ~80ms | ~30ms |
| **隐私** | 数据上传云端 | 部分本地 | 完全本地 |
| **离线** | 不支持 | 不支持 | 支持 |
| **部署复杂度** | 低 | 中 | 高 |
| **推荐指数** | ⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ |

## 3. 最佳实践框架

### 方案选择

**推荐方案：完全本地化部署（针对 i5-8259U + 16GB 内存优化）**

### 架构设计

```
用户查询
    │
    ▼
┌─────────────────────────────────────────────────────┐

│  短期记忆：OpenClaw In-memory (无需 Redis)        │
└─────────────────────────────────────────────────────┘
```

### 核心组件

| 组件 | 用途 | 配置 |
|------|------|------|
| **m3e-base** | 中文 Embedding | 768维，已缓存（推荐） |
| **PostgreSQL + pgvector** | 向量+结构化存储 | `localhost:5432` |
| ~~
| ~~Qdrant~~ | ~~向量数据库~~ | ~~可移除~~ |
| ~~Redis~~ | ~~会话缓存~~ | ~~不需要~~ |

### 为什么选择 m3e-base + PostgreSQL (pgvector)？

| 维度 | 原方案 (Qdrant+Redis) | 新方案 (pgvector) |
|------|----------------------|-------------------|
| **内存占用** | Qdrant + Redis + PG ≥ 1GB+ | PostgreSQL 一个容器 |
| **架构复杂度** | 3个服务 | 1个服务 |
| **中文检索** | nomic-embed-text 效果一般 | m3e-base 精度高 |
| **CPU 负载** | 3个容器调度 | 1个容器 |
| **维护成本** | 高 | 低 |

## 4. 具体操作步骤

### 4.1 前置准备

#### 系统要求

- Linux/macOS
- 至少 4GB 可用内存（用于 Embedding 模型）
- 10GB 磁盘空间

#### 安装基础依赖

```bash
# Ubuntu/Debian
sudo apt update
sudo apt install -y curl wget git

# PostgreSQL
sudo apt install postgresql postgresql-contrib

# Redis
sudo apt install redis-server

# Docker (用于 Qdrant)
sudo apt install docker.io docker-compose
```

#### 创建数据库

```bash
# 启动 PostgreSQL
sudo systemctl start postgresql
sudo systemctl enable postgresql

# 创建用户和数据库
sudo -u postgres psql << EOF
CREATE USER a1605 WITH PASSWORD '1605';
CREATE DATABASE openclaw OWNER a1605;
CREATE DATABASE memory OWNER a1605;
GRANT ALL PRIVILEGES ON DATABASE openclaw TO a1605;
GRANT ALL PRIVILEGES ON memory TO a1605;
EOF

# 启动 Redis
sudo systemctl start redis
sudo systemctl enable redis
```

### 4.2 部署 Qdrant 向量数据库

#### Docker 部署（推荐）

```bash

  --name qdrant \
  -p 6333:6333 \
  -p 6334:6334 \
  -v ~/data/qdrant:/qdrant/storage \
  qdrant/qdrant

# 验证

```

#### 或使用 Docker Compose

```yaml
# docker-compose.yml
version: '3.8'

    ports:
      - "6333:6333"
      - "6334:6334"
```

### 双记忆系统

本系统支持**两套记忆机制**：

| 记忆类型 | 用途 | 索引脚本 | 存储位置 |
|----------|------|----------|----------|
| **Agent 记忆** | AI 个人记忆、历史对话 | `sync_brain_ollama.py` | Qdrant (openclaw_memory) |
| **知识库** | 结构化知识文档 | `knowledge_embed.py` | Qdrant (knowledge-share) |

#### 使用场景

- **Agent 记忆**：当用户问 "上次我们讨论了什么？" → 检索 Agent 记忆
- **知识库**：当用户问 "关于 XXX 的知识" → 检索知识库文档

### 6.1 记忆模式概述

OpenClaw Agent 采用**双层记忆架构**，不依赖云端 API：

| 层级 | 存储方式 | 用途 | 检索方式 |
|------|----------|------|----------|
| **短期记忆** | `memory/YYYY-MM-DD.md` | 每日 raw 日志 | 手动文件读取 |
| **长期记忆** | `MEMORY.md` | 精选核心信息 | 手动文件读取 |
| **向量索引** | Qdrant (openclaw_memory) | 语义搜索 | `backup_memory_search.py` |

### 6.2 记忆工作流

```
用户提问
    │
    ▼
┌─────────────────────────────────────────────────────┐
│  1. 检查是否为长期记忆相关问题                        │
│     (上次讨论什么？之前做了什么？)                    │
└─────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────┐
│  2. 调用 backup_memory_search.py                   │
│     搜索 Qdrant (openclaw_memory)                   │
└─────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────┐
│  3. 如需更多上下文                                  │
│     读取 memory/YYYY-MM-DD.md                       │
└─────────────────────────────────────────────────────┘
    │
    ▼
结合记忆回答问题
```
