# 密码重置漏洞挖掘指南

> 来源：奇安信攻防社区
> 核心思路：站在攻击者角度，尝试劫持任意用户的密码重置流程

## 攻击流程

1. **初始化重置**：为目标用户发起密码重置请求
2. **拦截/篡改凭证**：获取或控制重置凭证（Token、验证码、USERID）
3. **接管流程**：将凭证转至攻击者控制
4. **完成重置**：利用凭证修改目标用户密码

---

## 漏洞类型与挖掘思路

### 1. 客户端状态校验不全

**原理**：服务器将关键状态（如"是否已验证"）委托给客户端存储，未在服务器端二次校验。

**利用**：
- 抓包修改响应包参数：`code` 改为 `0`，`false` 改为 `true`
- 修改 `"verified": false` → `"verified": true`

**挖掘思路**：
- 寻找前台"忘记密码"功能
- 修改客户端返回的状态值，观察服务器是否仅依据此值判断

---

### 2. 步骤分离与校验不足

**原理**：多步骤重置流程中，步骤间状态校验不足，可跳过关键验证。

**利用**：
- 直接访问后续步骤 URL（如 `/reset/step2`）
- 修改 user_id 为目标用户 ID

**挖掘思路**：
- 尝试直接跳转后续步骤
- 分析每步请求中的用户标识参数（如 `user_id`、`temp_token`）

---

### 3. 鉴权不严 - 可预测用户标识

**原理**：使用简单、可预测的参数作为用户唯一标识（如单调递增的 USERID）。

**利用**：
- 响应包修改：`"showResetPassword": false` → `true`
- 遍历 USERID 批量重置

**挖掘思路**：
1. **收集令牌样本**：反复触发功能，观察生成模式
2. **分析结构**：数字？字母？Base64？Hex？
3. **破解算法**：
   - 纯数字 → 可能是时间戳
   - 32位十六进制 → MD5/SHA256
   - 尝试在前端源码破解生成算法

---

### 4. 账号与校验参数未绑定

**原理**：接收端参数由客户端提供且可篡改，导致凭证发至攻击者控制地址。

**案例一：接收端篡改**
- 请求中邮箱参数可控：`email=attacker@email.com`
- 服务器仅校验验证码与邮箱绑定

**案例二：验证码转发**
- 关键参数后添加多个参数转发验证码

**案例三：令牌未绑定用户**
- 用户A验证后获取凭证
- 攻击者利用凭证有效期内重置用户B密码

**挖掘思路**：
1. 记录完整重置流程
2. 识别接收端参数：
   - 直接：`phone`, `email`, `mobile`, `receiver`
   - 间接：`user_id`, `uid`, `username`
3. **测试篡改**：替换为攻击者控制的接收端
4. **测试步骤关联**：检查各步骤用户身份是否一致
5. **测试绑定校验**：用目标用户的验证码重置他人密码

---

## 关键测试点

| 测试点 | 方法 |
|--------|------|
| 响应包篡改 | 修改 `true/false`，`0/1` |
| 步骤绕过 | 直接访问后续步骤 URL |
| ID 枚举 | 递增/递减 user_id |
| 接收端篡改 | 修改 email/phone 参数 |
| 验证码转发 | 添加多个接收端参数 |
| 令牌复用 | 利用有效令牌重置其他用户 |
