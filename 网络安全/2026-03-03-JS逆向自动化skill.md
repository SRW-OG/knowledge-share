# JS逆向自动化 Skill - JSRPC+Flask+autoDecoder 方案

## 一、问题现状：JS 逆向的痛点与挑战

### 背景描述

在前端安全测试中，**JS 逆向（JavaScript 逆向分析）** 是获取后端 API 签名/加密逻辑的关键技术。传统方法面临以下挑战：

- **定位加密函数困难**：需要手动在海量 JS 代码中追踪加密/签名逻辑
- **JSRPC 配置繁琐**：需要编写注册代码、编写 Python 后端、配置代理等
- **重复性工作**：每个目标都需要重复上述流程
- **与 Burp 联动困难**：难以实现端到端的自动化联调

### 风险评估

- **效率低下**：手动分析一个目标的加密逻辑可能需要数小时甚至数天
- **容易遗漏**：复杂的前端代码可能导致关键加密逻辑被忽略
- **反调试对抗**：越来越多的网站部署了反调试机制（Anti-Debug）

### 影响范围

- Web 安全测试工程师
- 渗透测试人员
- API 安全研究者

## 二、解决思路与方案对比

### 传统方案 vs 自动化方案

| 维度 | 传统 JSRPC 方案 | 本自动化方案 |
|------|-----------------|---------------|
| 函数定位 | 手动搜索 + 经验判断 | MCP 连接浏览器自动追踪 |
| 注册代码 | 手动编写 | AI 自动生成 |
| Python 后端 | 手动编写 Flask | AI 自动生成 |
| Burp 联动 | 手动配置 | autoDecoder 自动对接 |
| 反调试 | 手动绕过 | AntiDebug_Breaker 自动对抗 |
| 耗时 | 数小时 | 自动化执行，人工仅需输入目标信息 |

### 核心思路

**利用 AI 的 MCP（Model Context Protocol）和 Skill 技术，让 AI 自动完成：**
1. 连接真实浏览器，触发并跟踪 JS 加密链路
2. 定位 sign/enc/token 等关键参数
3. 生成 JSRPC 注入代码
4. 生成 Flask 代理代码
5. 输出 Burp autoDecoder 配置说明

## 三、最佳实践框架

### 系统架构

```
┌─────────────┐     ┌──────────────┐     ┌─────────────┐
│   用户输入   │ ──> │   Codex/AI   │ ──> │  MCP 浏览器 │
│ (目标URL等)  │     │  (Skill执行)  │     │  (DevTools) │
└─────────────┘     └──────────────┘     └─────────────┘
                                                  │
                                                  ▼
                    ┌──────────────┐     ┌─────────────┐
                    │  Burp Suite  │ <── │   Flask    │
                    │ autoDecoder  │     │   代理     │
                    └──────────────┘     └─────────────┘
```

### 核心组件

| 组件 | 用途 |
|------|------|
| **chrome-devtools-mcp** | MCP 协议连接 Chrome DevTools |
| **JSRpc** | 远程调用 JS 函数 |
| **Flask** | Python 代理服务器 |
| **autoDecoder** | Burp 插件，自动解码/编码请求 |
| **AntiDebug_Breaker** | 11 项反调试对抗能力 |

### Skill 工作流程

```
用户输入目标信息
    │
    ▼
1. MCP 连接浏览器，触发加密请求
    │
    ▼
2. 自动追踪 JS 执行链路，定位加密函数
    │
    ▼
3. 生成 JSRPC 注入代码 (jsrpc_inject_xxx.js)
    │
    ▼
4. 生成 Flask 代理代码 (flask_proxy_xxx.py)
    │
    ▼
5. 输出 Burp autoDecoder 配置说明
    │
    ▼
最终输出：可复用的加密/签名解决方案
```

## 四、具体操作步骤

### 前置条件

1. **安装 Chrome 扩展**（如果是 Codex/Claude 等平台）
2. **配置 chrome-devtools-mcp**
3. **启动 Chrome 远程调试模式**

### Step 1：配置 MCP 环境

**添加 chrome-devtools-mcp 服务：**

```bash
# Codex 示例
codex mcp add chrome-devtools -- npx -y chrome-devtools-mcp@latest
```

**修改配置文件 (~/.codex/config.toml)：**

```toml
[mcp_servers.chrome-devtools]
command = "npx"
args = ["-y", "chrome-devtools-mcp@latest"]
```

**启动 Chrome 远程调试：**

```bash
# macOS
/Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome \
    --remote-debugging-port=9222 \
    --remote-debugging-address=0.0.0.0

# Linux
google-chrome --remote-debugging-port=9222 --remote-debugging-address=0.0.0.0
```

### Step 2：使用 Skill

1. **下载 skills** 放置到平台的 skills 目录
   - Codex: `~/.codex/skills/`
   - 目录结构：`js-reverse-automation--skill/`

2. **在 AI 客户端中使用该 Skill**

3. **输入目标信息**：
   ```
   1、目标网址（完整 URL）：
   2、需要分析的加密参数名（如 sign / enc / token）：
   3、可复现请求示例（优先给 fetch/抓包原始请求）：
   4、环境限制（浏览器版本、是否需要代理/插件、是否允许注入）：
   ```

4. **等待自动化执行完成**

### Step 3：验证与联调

**1. 启动 JSRPC 服务**

```bash
# 启动 JSRPC 监听
python jsrpc_server.py
```

**2. 注入 JS 代码**

在浏览器 DevTools Console 中执行：
- 首先执行 `JsEnv_Dev.js`（JSRPC 环境初始化）
- 然后执行 AI 生成的 `jsrpc_inject_xxx.js`

**3. 测试 JSRPC 调用**

```bash
curl "http://127.0.0.1:12080/go?group=fausto&action=generate_sign&param=test"
```

**4. 启动 Flask 代理**

```bash
python flask_proxy_xxx.py
```

**5. 测试 Flask 加密**

```bash
curl -X POST http://127.0.0.1:8888/encode \
  -H "Content-Type: application/x-www-urlencoded" \
  --data-urlencode "dataBody=username=test&password=123456"
```

**6. 配置 Burp autoDecoder**

根据 AI 输出的配置说明，在 Burp Suite 中配置 autoDecoder 插件。

## 五、总结与建议

### 核心价值

| 能力 | 描述 |
|------|------|
| **自动化程度高** | 从函数定位到代码生成全流程自动化 |
| **端到端联调** | 完整支持 JSRPC → Flask → Burp 联动 |
| **反调试对抗** | 内置 11 项 AntiDebug 能力 |
| **可复用性强** | 生成的代码可保存复用 |

### 适用场景

- ✅ 快速落地前端签名/加密参数逆向
- ✅ 将 JS 逆向逻辑封装为可复用代码
- ✅ 与 Burp 配合进行抓包、改包测试

### 局限性

- ⚠️ 需要目标站点允许浏览器调试（无 CSP 严格限制）
- ⚠️ 某些高级反调试可能需要额外对抗
- ⚠️ 依赖 MCP 服务的稳定性
