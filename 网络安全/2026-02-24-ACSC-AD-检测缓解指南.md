## 摘要

2024年9月，澳大利亚信号理事会网络安全中心 (ASD ACSC) 联合 CISA、NSA、CCCS、NCSC-UK、NCSC-NZ 发布了一份关于**检测和缓解 Active Directory  compromise** 的联合指南。

该指南涵盖了**17种最常见的 AD compromise 技术**，提供了检测和缓解策略。Active Directory 是全球企业 IT 网络中**最广泛使用的身份认证和授权解决方案**，也是攻击者的重点目标。

## Active Directory 概述

### 核心组件

| 组件 | 说明 |
|------|------|
| **Domain (域)** | AD 的基本逻辑单元，包含共享同一 AD 数据库的对象 |
| **Domain Controllers (DC)** | 运行 AD 的服务器，负责用户认证和安全策略执行 |
| **Forest (林)** | 一个或多个域的集合，共享通用架构和配置 |
| **Organizational Units (OU)** | 容器，用于组织域内的用户、计算机和资源 |
| **Global Catalog (GC)** | 分布式数据仓库，包含 AD 林中所有对象的信息 |
| **Schema** | AD 中对象及其属性的定义 |

### 核心功能

- **用户和组管理** - 创建账户、分配组、控制访问
- **资源管理** - 集中控制文件共享、打印机、网络访问
- **安全管理** - 强制执行密码策略、软件限制、访问控制列表
- **复制** - AD 数据在多个 DC 间复制，确保高可用性

## AD 安全风险分析

### 为什么 AD 容易被 compromise？

1. **宽松的默认设置** - 默认配置允许过多权限
2. **复杂的关系网络** - 用户、系统间存在隐藏关系
3. **支持遗留协议** - NTLM 等不安全协议仍被支持
4. **缺乏诊断工具** - 难以发现安全问题
5. **攻击面大** - 每个用户都有足够权限发现和利用弱点

### 攻击影响

- 获取 AD 控制权 → 获得所有受 AD 管理的系统和用户的特权访问
- 可绑过其他安全控制，访问邮件、文件服务器等关键系统
- 可通过 Microsoft Entra ID 扩展到云端系统
- 可建立持久化，即使重置密码也能远程登录
- 高级攻击者可能在 AD 中潜伏数月甚至数年

## 17种常见攻击技术

根据 MITRE ATT&CK 框架，指南覆盖了以下主要技术类别：

### 1. 凭证攻击

| 技术 | 描述 |
|------|------|
| 密码喷洒 | 利用常见密码尝试大量账户 |
| 凭证转储 | 从内存或磁盘提取凭据 (LSASS, SAM 数据库) |
| 暴力破解 | 针对账户的密码猜测攻击 |
| NTLM  relay | 中继 NTLM 认证请求 |

### 2. 权限提升

| 技术 | 描述 |
|------|------|
| 滥用 DCSync | 模拟域控制器同步请求获取凭据 |
| Kerberoasting | 请求 TGS 票证并离线破解 |
| ACL  abuse | 滥用访问控制列表配置 |
| SID History | 利用 SID 历史属性提权 |

### 3. 横向移动

| 技术 | 描述 |
|------|------|
| Pass-the-Hash | 使用哈希值而非密码认证 |
| Pass-the-Ticket | 伪造 Kerberos 票证 |
| Remote Services | 通过 SMB、RDP 等远程服务移动 |
| Exploitation of Remote Services | 利用远程服务漏洞 |

### 4. 持久化

| 技术 | 描述 |
|------|------|
| Golden Ticket | 创建伪造的 TGT 票证 |
| Silver Ticket | 伪造 TGS 票证 |
| Skeleton Key | 在 DC 植入后门密钥 |
| SID History | 持久化属性注入 |
| DSRM 密码 | 修改 DSRM 管理员密码 |

## 详细操作指南

### 1. 账户锁定策略

**目的**: 防止暴力破解和密码喷洒

```powershell
# 使用组策略设置 (GPO)

# 计算机配置 → Windows 设置 → 安全设置 → 账户策略 → 账户锁定策略
# 账户锁定阈值: 5 次无效登录
# 账户锁定时间: 30 分钟
# 重置账户锁定计数器: 30 分钟

# PowerShell 验证
net accounts

# 查看锁定账户
Get-ADAccountLockoutStatus -Identity username
```

**检测查询**:
```powershell
# 查找被锁定的账户
Search-ADAccount -LockedOut | Select Name, LastLogonDate

# 查看失败登录事件 (Event ID 4625)
Get-WinEvent -FilterHashtable @{LogName='Security';ID=4625} -MaxEvents 100 |
  Where-Object { $_.TimeCreated -gt (Get-Date).AddHours(-1) } |
  Select-Object TimeCreated, Message
```

### 2. LSASS 加固

**目的**: 防止凭证从内存中提取

```powershell
# 启用 Credential Guard (需要 Windows 10/Server 2016+)

# 方法1: 组策略
# 计算机配置 → 管理模板 → 系统 → 设备防护 → 启用 Credential Guard

# 方法2: PowerShell (需要 Enterprise/Education)
Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\DeviceGuard" -Name "EnableVirtualizationBasedSecurity" -Value 1 -Type DWord
Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\DeviceGuard" -Name "RequirePlatformSecurityFeatures" -Value 1 -Type DWord

# 限制 LSASS 进程调试
# 计算机配置 → 管理模板 → 系统 → 调试工具 → 防止调试工具访问 LSASS
```

**检测规则 (Sysmon Event ID 10)**:
```xml
<!-- 检测 LSASS 进程访问 -->
<RuleGroup name="LSASS Access">
  <ImageLoad condition="contains">lsass.exe</ImageLoad>
    <TargetImage condition="contains">lsass.exe</TargetImage>
      <GrantedAccess condition="contains any">0x1400;0x1000;0x40;0x10;0x1;0x2;0x4;0x8;0x20</GrantedAccess>
  </ImageLoad>
</RuleGroup>
```

### 3. NTLM 和 SMB 签名

**目的**: 防止 NTLM Relay 和 SMB Relay 攻击

```powershell
# 禁用 NTLMv1
# 域控制器上执行
New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\LanmanServer\Parameters" -Name "RequireSecuritySignature" -Value 1 -Type DWord -Force

# 或通过 GPO: 计算机配置 → Windows 设置 → 安全设置 → 本地策略 → 安全选项
# → "Microsoft 网络客户端: 对数字签名的通信(如果服务器同意)": 启用
# → "Microsoft 网络客户端: 对数字签度的通信(总是)": 启用

# 限制 NTLM 认证
# GPO: 计算机配置 → Windows 设置 → 安全设置 → 本地策略 → 安全选项
# → "网络安全: 限制 NTLM: 传入 NTLM 流量": 拒绝所有
# → "网络安全: 限制 NTLM: 域成员 NTLM 认证": 只拒绝 NTLMv1

# 验证 NTLM 设置
reg query "HKLM\SYSTEM\CurrentControlSet\Control\Lsa" /v LMCompatibilityLevel
```

### 4. DCSync 防护

**目的**: 防止攻击者模拟域控制器同步请求

```powershell
# 检查谁有 DCSync 权限
# 需要 Replication Get Changes All 和 Replication Get Changes in Filtered Set

# 使用 PowerShell (需要 AD RSAT)
Import-Module ActiveDirectory

# 查看具有 DCSync 权限的账户
$ DCSyncUsers = Get-ADObject -Filter {
    -or {
        (objectClass -eq 'user')
        (objectClass -eq 'computer')
    }
} -Properties msDS-ReplicationGetChangelog,msDS-ReplicationGetChangesAll -SearchBase (Get-ADDomain).UsersContainer

# 或使用 Purple Knight
# https://www.semperis.com/purple-knight/

# 移除不必要的 DCSync 权限
# 在 ADUC 中，右键账户 → 属性 → 安全 → 移除 "Replicating Directory Changes All"

# 监控 DCSync (事件 4662 + 特定对象)
Get-WinEvent -FilterHashtable @{LogName='Security';ID=4662} -MaxEvents 100 |
  Where-Object { $_.Message -match "Replicating Directory Changes" }
```

### 5. Kerberoasting 防护

**目的**: 防止请求 TGS 票证后离线破解

```powershell
# 1. 为服务账户设置强密码 (≥25 字符，随机生成)
# 建议使用 Managed Service Accounts (MSAs) 或 Group Managed Service Accounts (gMSA)

# 2. 定期轮换服务账户密码
Update-MSAPassword -Identity ServiceAccountName

# 3. 限制 Kerberos 预身份验证
# 确保用户账户启用 "Do not require Kerberos preauthentication"

# 4. 监控异常 TGS 请求 (事件 4769)
Get-WinEvent -FilterHashtable @{LogName='Security';ID=4769} -MaxEvents 100 |
  Where-Object { $_.Message -match "0x0" } |
  Select-Object TimeCreated, AccountName, ServiceName

# 5. 使用 AES 加密 (优先)
Set-ADAccountControl -Identity ServiceAccountName -KerberosEncryptionType AES128,AES256

# 检测易受攻击的服务账户
# 查找 SPN 指向的用户账户
Get-ADUser -Filter {ServicePrincipalName -like "*"} -Properties ServicePrincipalName
```

### 6. ACL 加固

**目的**: 防止滥用访问控制列表权限

```powershell
# 1. 检查用户对象的敏感 ACL
Import-Module ActiveDirectory

# 查看用户 ACL
Get-Acl "AD:\CN=Username,CN=Users,DC=domain,DC=com" |
  Select-Object -ExpandProperty Access |
  Where-Object { $_.ActiveDirectoryRights -match "WriteProperty|GenericAll" }

# 2. 查找具有 WriteProperty 权限的账户
# 特别是针对重要属性: member, scriptPath, pwdLastSet, sidHistory

# 3. 移除过于宽泛的权限
# 使用 Active Directory Administrative Center (ADAC)

# 4. 定期审计 ACL 变更
# 监控事件 5136 (Directory Service Changes)

# 5. 使用第三方工具
# BloodHound: 分析 AD 权限路径
# PingCastle: 评估 AD 安全
```

### 7. SID History 清理

**目的**: 防止通过 SID History 提权

```powershell
# 1. 检查账户的 SID History
Get-ADUser -Identity username -Properties SIDHistory | Select-Object SIDHistory

# 2. 清除 SID History
# 注意: 这可能会影响已授予的权限!

# 备份当前 SID History
$sidHistory = (Get-ADUser -Identity username -Properties SIDHistory).SIDHistory
# 如需恢复，保存此信息

# 清除 SID History
Set-ADUser -Identity username -Clear SIDHistory

# 3. 监控 SID History 修改 (事件 4765, 4766)
Get-WinEvent -FilterHashtable @{LogName='Security';ID=4765} -MaxEvents 50

# 4. 防止 SID History 滥用
# 确保只有必要账户有 WriteProperty 权限
```

### 8. PTH (Pass-the-Hash) 防护

**目的**: 防止使用哈希值认证

```powershell
# 1. 启用Restricted Admin Mode
# 客户端需要:
New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\Lsa" -Name "DisableRestrictedAdmin" -Value 0 -Type DWord -Force

# 2. 部署 Credential Guard (见上文)

# 3. 限制管理员登录范围
# GPO: 计算机配置 → Windows 设置 → 安全设置 → 本地策略 → 用户权限分配
# → "允许通过远程桌面服务登录": 只包含必要用户
# → "拒绝从网络访问此计算机": 包含所有非管理员

# 4. 使用 Protected Users 安全组
# 将高权限账户加入 Protected Users 组
Add-ADGroupMember -Identity "Protected Users" -Members "Admin1","Admin2"

# 5. EPA (Extended Protection for Authentication)
# GPO: 计算机配置 → 管理模板 → Windows 组件 → 安全设置 → 高级安全设置
```

### 9. Kerberos 强化

**目的**: 全面强化 Kerberos 认证

```powershell
# 1. 启用 AES 加密
# 域级别
Set-ADDomain -Identity domain.com -KerberosEncryptionType AES128,AES256

# 2. 禁用 NTLM 认证 (见上文)

# 3. 设置票据生命周期
# 默认: 10 小时 (TGT), 10 小时 (TGS)
# 建议: 高敏感性账户使用更短生命周期

# 4. KRBTGT 密码轮换 (至少每 30 天)
# 2024年3月后，可以使用 Reset-MSKrbtgtKey 或 GoldenPassPhrase

# 5. 检查 Kerberos 策略
# 使用 klist 查看缓存票据

# 6. 监控异常 Kerberos 活动
# 4768: TGT 请求
# 4769: TGS 请求 (重点关注 0x0 错误码)
# 4770: 票据续期

Get-WinEvent -FilterHashtable @{LogName='Security';ID=4769} -MaxEvents 100 |
  Where-Object { $_.TimeCreated -gt (Get-Date).AddHours(-1) } |
  Select-Object TimeCreated, AccountName, ServiceName, IpAddress
```

### 10. RDP 加固

**目的**: 防止 RDP 横向移动和会话劫持

```powershell
# 1. 启用 Network Level Authentication (NLA)
# GPO: 计算机配置 → 管理模板 → Windows 组件 → 远程桌面服务 → 安全
# → "要求用户使用网络级别身份验证连接"

# 2. 限制管理员登录
# GPO: 计算机配置 → Windows 设置 → 安全设置 → 本地策略 → 用户权限分配
# → "允许通过远程桌面服务登录"

# 3. 禁用 RDP 管理员模式
Set-ItemProperty -Path "HKLM:\System\CurrentControlSet\Control\Lsa" -Name "DisableRestrictedAdmin" -Value 0 -Type DWord

# 4. 更改默认 RDP 端口 (3389 → xxxx)
# 注册表: HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp
# PortNumber: xxxx

# 5. 监控 RDP 登录
# 事件 4624 (登录类型 10 = RDP)
# 事件 4648 (显式凭据登录)

Get-WinEvent -FilterHashtable @{LogName='Security';ID=4624} -MaxEvents 100 |
  Where-Object { $_.Message -match "Type:.*10" } |
  Select-Object TimeCreated, AccountName, IpAddress
```

### 11. Golden/Silver Ticket 防护

**目的**: 防止伪造 Kerberos 票证

```powershell
# 1. KRBTGT 密码轮换 (每 30 天)
# 使用微软官方工具
Import-Module "$env:SystemRoot\System32\KdsCli.dll"

# 轮换 KRBTGT 密码 (两次，间隔至少 10 小时)
Reset-KrbTgtPassword -DomainController DC01 -ForceReset -WhatIf
# 第一次轮换后，等待 10+ 小时再执行第二次

# 2. 使用 Protected Users 组
Add-ADGroupMember -Identity "Protected Users" -Members "Domain Admins"

# 3. 设置 SID Filtering (域信任)
# 启用 SID History 筛选，防止跨域攻击

# 4. 监控票证异常
# 4770: 票据续期 (关注异常时间/来源)
# 4769: 服务票证 (关注不存在服务的请求)

# 5. 检查现有 Golden Ticket
# BloodHound 检查 KRBTGT 账户的异常权限

# 6. 限制票据有效期
# 域策略: 计算机配置 → Windows 设置 → 安全设置 → 账户策略 → Kerberos 策略
# → 票据最大生存期: 10 小时
```

## 缓解措施

### 1. 密码策略 (CIS Benchmark)

```powershell
# 建议配置
# 最小密码长度: ≥14 字符
# 密码复杂性: 必须包含大小写字母、数字、符号
# 密码历史: 防止重用前 24 个密码
# 账户锁定: 5 次失败后锁定

# 账户锁定策略
net accounts /lockoutthreshold:5
net accounts /lockoutduration:30
net accounts /lockoutwindow:30
```

### 2. 身份验证保护

| 措施 | 说明 |
|------|------|
| **禁用 NTLMv1** | 高风险遗留协议 |
| **启用 LDAP 签名** | 防止 LDAP relay |
| **启用 SMB 签名** | 防止 SMB relay |
| **强制 Kerberos 预身份验证** | 防止 AS-REP Roasting |
| **部署 LAPS** | 本地管理员密码随机化 |

### 3. 特权访问管理 (PAM)

```powershell
# 将 Administrator 账户标记为敏感，禁止委派
Set-ADAccount -Identity Administrator -AccountNotDelegated $true

# JIT (Just-In-Time) 访问
# 使用 PAM 解决方案限时提升权限
```

### 4. 组策略加固

- 限制 Domain Admins、Enterprise Admins、Schema Admins 组成员
- 仅为必要人员分配特权
- 启用组成员变更告警
- 禁用不必要的网络协议

### 5. 审计与监控

```powershell
# 关键审计策略
AuditLogonEvents: Success, Failure
AuditAccountManagement: Success, Failure
AuditDirectoryServiceAccess: Success, Failure
AuditPolicyChange: Success, Failure
```

**需监控的关键事件**:
- 4768/4769 - Kerberos TGT 请求/服务票证
- 4624/4625 - 账户登录成功/失败
- 4732/4733 - 组成员添加/删除
- 4662 - 对象操作
- 7045 - 新服务安装

### 6. 资产清单与分类

收集并维护 AD 中所有资产的清单，按关键程度分类：
- **关键** - 域控制器、高权限账户
- **重要** - 业务应用服务器、数据库
- **一般** - 普通工作站、用户设备

### 7. 补丁管理

- 确保所有域控制器及时安装安全补丁
- 更新 AD 相关软件 (DNS, DHCP 等)
- 定期评估漏洞风险

### 8. DNS/DHCP 加固

- 保护 AD 使用的 DNS 区域
- 防止 DNS 缓存投毒
- 加固 DHCP 配置防止未授权设备接入

## 检测建议

### 异常指标

| 指标类型 | 检测方法 |
|----------|----------|
| 异常登录时间 | 监控非工作时间的登录 |
| 特权账户使用 | 监控高权限账户的实时访问 |
| 大规模枚举 | 检测快速的账户/组枚举行为 |
| 凭据转储 | 监控 LSASS 进程访问 |
| 横向移动 | 监控异常主机间认证 |

### SIEM 集成

建议部署 SIEM 系统集中分析：
- Windows Event Logs
- Azure AD 审计日志
- 网络流量日志
- DNS 查询日志

## 实施优先级

### 第一阶段 (紧急)

1. 禁用 NTLMv1
2. 启用账户锁定策略 (5次失败)
3. 审计特权组成员
4. 部署 LAPS

### 第二阶段 (重要)

1. 实施 PAM 解决方案
2. 启用 Kerberos 强化
3. 部署 SIEM 监控
4. 建立基线行为分析

### 第三阶段 (持续)

1. 定期渗透测试
2. 红蓝对抗演练
3. 完善事件响应预案
4. 持续监控和优化

## 总结

Active Directory 是企业网络的核心目标。实施本指南建议的缓解措施可显著提升 AD 安全性：

- **减少攻击面** - 禁用遗留协议、限制权限
- **提升检测能力** - 全面审计、SIEM 监控
- **加速响应** - 事件响应流程、清晰的分级
