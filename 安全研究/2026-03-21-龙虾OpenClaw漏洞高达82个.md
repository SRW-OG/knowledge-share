# 龙虾 OpenClaw 漏洞高达 82 个

## 1. 问题现状

### 背景描述

自 2026 年 1 月至 2026 年 3 月 9 日，国家信息安全漏洞库（CNNVD）共采集 OpenClaw（代号"龙虾"）漏洞 **82 个**。

### 漏洞等级分布

| 等级 | 数量 |
|------|------|
| 超危（Critical） | 12 |
| 高危（High） | 21 |
| 中危（Medium） | 47 |

### 漏洞类型覆盖

- **访问控制错误**：可能被用于未授权访问
- **代码问题**：逻辑缺陷、资源管理错误
- **路径遍历**：可导致文件读取或写入
- **敏感数据泄露**：凭据、配置外泄
- **远程代码执行（RCE）**：最高风险，可完全控制主机

### 影响评估

82 个漏洞意味着 OpenClaw 作为具备完整系统访问权限的 AI 控制平面，其攻击面相当广泛。攻击者可能利用这些漏洞实现：**未授权访问 → 敏感数据窃取 → 权限提升 → 远程代码执行**。

## 2. 解决思路与方案对比

### 核心风险

OpenClaw 的定位是「个人 AI 助手」，拥有极高权限。一旦漏洞被利用，攻击者获得的不是受限 Shell，而是具备完整操作系统控制权的自动化代理。

### 部署方案对比

| 方案 | 安全性 | 便利性 | 推荐度 |
|------|--------|--------|--------|
| 工作机直接安装 | ❌ 高风险 | 高 | 不推荐 |
| Docker 容器隔离 | ✅ 中高 | 中 | 推荐 |
| 虚拟机/闲置电脑 | ✅ 高 | 低 | 推荐 |
| 大厂云端版本 | ✅ 高 | 高 | 推荐（隐私/功能权衡）|

## 3. 最佳实践框架

### 推荐部署架构

```
[物理/云主机]
  └── Docker 容器（或虚拟机）
        └── OpenClaw（权限最小化配置）
```

### 权限管控原则

- **最小权限**：财务、本地文件、命令执行权限须手工确认
- **Token 上限**：设定 API 用量上限，防止异常消耗
- **技能审核**：安装官方审核技能（如 skill-vetter）检测恶意内容

## 4. 具体操作步骤

### Step 1：隔离安装（推荐 Docker）

```bash
# 安装 Docker（若未安装）
curl -fsSL https://get.docker.com | sh

# 创建专用网络
docker network create openclaw-net

# 以非 root 用户运行（若 OpenClaw 支持）
docker run -d \
  --name openclaw \
  --network openclaw-net \
  -p 127.0.0.1:18789:18789 \
  openclaw/openclaw:latest
```

### Step 2：修改默认端口，不暴露公网

```bash
# 在 openclaw.json 中修改端口
# 将默认端口改为仅本地监听
{
  "gateway": {
    "port": 18789,
    "bind": "127.0.0.1"   // 仅本地访问，不暴露公网
  }
}
```

### Step 3：权限缩减配置

```json
{
  "capabilities": {
    "file_access": "read-only",
    "command_execution": false,
    "financial_operations": false,
    "auto_confirm": false
  }
}
```

### Step 4：设定 Token 上限与监控

```bash
# 在 openclaw.json 中配置
{
  "limits": {
    "daily_token_budget": 100000,
    "alert_threshold": 0.8
  }
}
```

### Step 5：定期检查更新

```bash
openclaw update
# 关注 CNNVD 漏洞公告：https://www.cnnvd.org.cn
```

## 5. 总结与建议

### 适用性判断

**推荐安装** 的人群：
- 具备基本网络安全知识
- 有明确使用需求
- 能在隔离环境中运行

**慎重考虑安装** 的人群：
- 不理解大部分安全术语
- 无明确使用需求
- 期望「装上就能自动干活」

### 核心建议

1. **隔离优先**：不用工作机直接安装，用 Docker/虚拟机
2. **最小暴露**：更改端口，仅本地访问，禁公网面板
3. **权限最小化**：缩减财务/文件/命令执行权限
4. **用量管控**：设定 Token 上限，防止异常消耗
5. **保持更新**：及时修补漏洞，关注 CNNVD 公告

> 82 个漏洞本身不可怕，可怕的是用户不具备判断哪些权限可以开放的安全认知。安全从了解自己的攻击面开始。
