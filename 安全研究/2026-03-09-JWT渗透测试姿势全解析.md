# JWT：渗透测试姿势全解析（含实战）

## 1. 问题现状 (Current Status & Problem Analysis)

### 背景描述

在渗透测试过程中，尤其是针对小程序资产的测试，经常会遇到 Cookie 字段以 `eyJ` 开头的字符串（Base64 编码的 JWT）。渗透测试人员常常面临无法修改敏感字段从而实现越权的困境。

### 风险评估

- **未授权访问**：攻击者可通过 JWT 漏洞绕过身份认证，获取管理员权限
- **垂直越权**：普通用户可利用 JWT 漏洞提升为管理员
- **水平越权**：可修改其他用户的身份标识（如 uid、userid）

### 影响范围

- 使用 JWT 进行身份认证的 Web 应用
- 小程序后端 API
- 移动应用后端服务

---

## 2. 解决思路与方案对比 (Solution Options & Analysis)

### JWT 基本原理

JWT（JSON Web Token）由三部分组成，用 `.` 分隔：
1. **Header（头部）**：定义加密算法和密钥 ID
2. **Payload（载荷）**：包含身份认证的核心字段
3. **Signature（签名）**：对前两部分的签名验证

### 攻击思路对比

| 攻击方式 | 适用场景 | 难度 | 危害程度 |
|----------|----------|------|----------|
| 有缺陷的 JWT 校验 | 使用 decode() 而非 verify() | 低 | 高 |
| 空密码算法 (none) | 未严格校验 alg 参数 | 低 | 高 |
| 密钥可爆破 | 使用弱口令密钥 (HS256) | 中 | 高 |
| JWK 注入 | 非对称算法未严格校验公钥白名单 | 中 | 高 |
| JKU 注入 | 远程加载公钥未校验 | 中 | 高 |
| 算法混淆 | RS256→HS256 利用公钥 | 高 | 高 |

## 3. 最佳实践框架 (Best Practice Framework)

### 渗透测试检查清单

1. **识别 JWT**：检查 Cookie/Header 中是否包含 Base64 编码的 JWT（通常以 `eyJ` 开头）
2. **分析算法**：
   - 对称加密 (HS256) → 尝试爆破密钥
   - 非对称加密 (RS256) → 尝试 JWK/JKU 注入
3. **代码审计**：检查是否使用了不安全的 decode() 方法
4. **测试越权**：修改 sub/uid/userid 等字段尝试越权

## 4. 具体操作步骤 (Implementation Steps)

### 步骤 1：有缺陷的 JWT 校验

**原理**：开发者使用 `decode()` 而非 `verify()` 方法，仅解码不验证签名。

**实战操作**：
```bash
# 1. 登录获取 JWT
# 2. 解码 JWT，修改 sub 字段为 administrator
# 3. 使用修改后的 JWT 访问管理员路径
```

### 步骤 2：空密码算法 (Alg=None)

**原理**：alg 参数设置为 none 时，签名不生效。

**实战操作**：
```bash
# 1. 登录获取 JWT
# 2. 在 jwt.io 中修改：
#    - alg: "none"
#    - sub: "administrator"
# 3. 删除签名部分（末尾保留空字符串）
# 4. 使用修改后的 JWT 访问管理员路径
```

### 步骤 3：密钥可爆破

**原理**：HS256 对称加密使用弱口令密钥。

**实战操作**：
```bash
# 1. 提取 JWT 到 jwt.txt
# 2. 使用 hashcat 爆破
hashcat -m 16500 -a 0 jwt.txt jwt.secrets.list --force

# 3. 爆破成功后，使用密钥修改 JWT
# 4. 访问管理员后台
```

### 步骤 4：JWK 注入

**原理**：JWT 内部包含公钥且未严格校验。

**实战操作**：
```bash
python jwt_tool.py <jwt> -I -pc sub -pv administrator -hc kid -hv jwt_tool -X i
```

### 步骤 5：JKU 注入

**原理**：公钥通过远程 URL 加载且未校验。

**实战操作**：
```bash
python jwt_tool.py <jwt> -I -pc sub -pv administrator -hc kid -hv jwt_tool -X s -ju <公钥URL>
```

### 步骤 6：算法混淆

**原理**：将 RS256 改为 HS256，利用公开的 RSA 公钥作为共享密钥。

**实战操作**：
```bash
# 1. 获取 RSA 公钥，转换为 PEM 格式
# 2. 使用 jwt_tool 进行算法混淆
python jwt_tool.py <jwt> -X k -pk key.pem -I -pc sub -pv administrator

# 3. 使用生成的 JWT 访问
```

## 5. 总结与建议 (Summary & Recommendations)

### 渗透测试要点

1. **先看算法**：判断对称/非对称
2. **对症下药**：
   - HS256 → 爆破密钥 / none 算法
   - RS256 → JWK/JKU 注入 / 算法混淆
3. **关注 kid 参数**：可能存在 SQL 注入、目录遍历

### 防御建议

| 防御措施 | 说明 |
|----------|------|
| 严格校验算法 | 禁止 alg=none，白名单算法列表 |
| 使用安全库 | 使用 verify() 而非 decode() |
| 强密钥策略 | 使用强随机密钥，定期轮换 |
| 公钥白名单 | JWK/JKU 必须严格校验来源 |
| 定期审计 | 代码审计 + 渗透测试 |

### 总结口诀

> 先看加密算法，如果是对称加密，就尝试爆破密钥，或设置 none 算法；非对称算法尝试是否存在 JWK、JKU，或 SQL 注入/目录遍历。
