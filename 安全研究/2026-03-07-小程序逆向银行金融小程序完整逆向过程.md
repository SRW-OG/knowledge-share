## 二、加密逻辑分析

通过微信开发者工具打开反编译后的代码进行分析。

### 2.1 加密算法确认

发现使用的是标准的**国密SM算法**，主要包括：
- **SM4**：对称加密
- **SM2**：非对称加密
- **SM3**：哈希签名

### 2.2 请求加密流程

```
1. 生成随机 SM4 密钥 g = random(32)  // 32字节随机密钥

2. 加密请求数据 bizContent = sm4.encrypt(JSON.stringify(data), g)

3. 加密 SM4 密钥 encryptionKey = sm2.doEncrypt(g, publicKey)

4. 保存密钥 codeKey = g  // 保存在内存中，用于后续解密响应

5. 发送到服务器
   {
     bizContent: "...",      // SM4 加密的数据
     encryptionKey: "...",    // SM2 加密的SM4密钥
     excerpt: "..."           // SM3摘要
   }
```

### 2.3 响应解密流程

```
6. 服务器处理
   - 使用 SM2 私钥解密 encryptionKey → 得到 SM4 密钥
   - 使用 SM4 密钥解密 bizContent → 得到原始请求数据
   - 处理业务逻辑
   - 使用相同的 SM4 密钥加密响应数据 → rtnResponse

7. 客户端接收响应
   response = {
     rtnCode: "000000",
     rtnResponse: "..."  // SM4 加密的响应数据
   }

8. 客户端解密响应
   decrypted = o.sm4.decrypt(response.rtnResponse, codeKey)
   // 加密的响应数据、之前保存的 SM4 密钥

9. 解析
   data = JSON.parse(decrypted)
```

### 2.4 混合加密方案特点

这是一个典型的**混合加密方案**：

| 加密算法 | 用途 | 优势 |
|----------|------|------|
| **SM4** | 对称加密，加密请求/响应数据 | 高效、快速 |
| **SM2** | 非对称加密，保护 SM4 密钥 | 安全、密钥分发方便 |
| **SM3** | 哈希签名，校验请求合法性 | 完整性保护 |

## 三、动态调试

### 3.1 调试工具

推荐使用 **WechatOpenDevTools** 可以直接在微信小程序里调出F12控制台。

> 注意：该工具目前已不支持最新版微信，旧版微信登录时会强制要求更新。

作者使用的是**微信开发者工具**直接运行反编译的代码。

### 3.2 调试方法

1. 分别在加密和解密的对应位置打上断点
2. 验证输出了明文请求和响应

### 3.3 攻击验证

尝试修改请求和响应内容：
- 断点打太晚 → 签名校验失败
- 提前打断点 → 修改成功，签名直接绕过

## 四、关键代码分析

### 4.1 请求加密

```javascript
// 生成随机 SM4 密钥
g = random(32)

// 加密请求数据
bizContent = sm4.encrypt(JSON.stringify(data), g)

// 加密 SM4 密钥
encryptionKey = sm2.doEncrypt(g, publicKey)

// 保存密钥用于后续解密
codeKey = g
```

### 4.2 响应解密

```javascript
// 使用之前保存的 SM4 密钥解密
decrypted = o.sm4.decrypt(response.rtnResponse, codeKey)

// 解析 JSON
data = JSON.parse(decrypted)
```
