# 冰凌：提示词注入辅助工具

## 1. 问题现状 (Current Status & Problem Analysis)

### 背景描述

随着大语言模型（LLM）在企业级应用中的广泛部署，提示词注入（Prompt Injection）已成为 AI 安全领域最关键的攻击向量之一。攻击者通过精心构造的输入，使 AI 模型忽略安全对齐，执行非预期的指令。

**现有工具的局限性：**
- P4RS3LT0NGV3 等早期工具功能分散，缺乏统一界面
- 手动变换提示词效率低下，难以批量测试
- 缺乏对变形效果的可视化反馈

### 风险评估

| 风险类型 | 描述 | 严重程度 |
|----------|------|----------|
| 指令注入 | 绕过安全过滤执行特权指令 | 高 |
| 信息泄露 | 通过注入提取系统提示词或上下文 | 高 |
| 级联攻击 | 污染上下文影响后续交互 | 中 |

### 影响范围

- 使用 LLM API 的第三方应用
- 内置 AI 助手的操作系统和软件
- 基于 RAG 架构的知识库系统

---

## 2. 解决思路与方案对比 (Solution Options & Analysis)

### 方案一：冰凌（BingLing）

**核心思路**：提供一站式提示词注入辅助平台，集成多种变换手法，支持可视化配置。

**优点**：
- 界面友好，操作简便
- 支持多种变形技术统一调用
- 可配置 API 或本地 Ollama

**缺点**：
- 云端 API 依赖外部服务
- 部分功能需授权测试

### 方案二：纯手工构造

**核心思路**：安全研究人员手动编写注入 payload。

**优点**：
- 无需依赖工具
- 针对性强

**缺点**：
- 效率极低
- 难以系统化测试

### 方案三：ASCII Smuggler 在线版

**核心思路**：使用 EmbraceTheRed 的 ASCII 走私技术。

**优点**：
- 成熟技术方案
- 在线即可使用

**缺点**：
- 功能单一
- 无 AI 辅助变形

### 方案对比表

| 方案 | 学习成本 | 效率 | 功能覆盖 | 适用场景 |
|------|----------|------|----------|----------|
| 冰凌 | 低 | 高 | ★★★★★ | 快速测试、CTF |
| 手工构造 | 高 | 低 | ★★☆☆☆ | 针对性研究 |
| ASCII Smuggler | 中 | 中 | ★★★☆☆ | 字符走私专项 |

## 3. 最佳实践框架 (Best Practice Framework)

### 方案选择

**推荐使用冰凌作为主要测试工具**，理由如下：

1. **功能集成度高**：文本变换、资源消耗、注入技术等模块统一管理
2. **可视化反馈**：支持 token 可视化，直接观察切分效果
3. **多模型支持**：可对接 OpenAI API 或第三方中转站，也支持云端 Ollama

### 架构设计

```

│                      冰凌前端界面                         │
├─────────────┬─────────────┬─────────────┬───────────────┤
│  文本变换    │   资源消耗   │   注入技术   │    AI改写     │
├─────────────┼─────────────┼─────────────┼───────────────┤
│  • Emoji注入 │ • 输入扰动   │ • 预置模板   │ • 越狱大师    │
│  • 拆分器    │ • 字符映射   │ • ASCII走私  │ • 自定义加载  │
│  • 解码器    │ • 随机变化   │ • 注入技巧   │              │
├─────────────┴─────────────┴─────────────┴───────────────┤

└─────────────────────────────────────────────────────────┘
```

### 关键组件

| 组件 | 功能 |
|------|------|
| 文本变换模块 | 多种编码、拆分、Emoji 注入 |
| 资源消耗模块 | 能耗攻击，生成大文本消耗 token |
| 注入技术库 | 收集整理的注入技巧参考 |
| AI 改写模块 | 利用 LLM 自动生成变形 payload |
