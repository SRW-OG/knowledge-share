# 【应急响应】记一次VPS反弹shell告警处置

## 1. 问题现状 (Current Status & Problem Analysis)

### 背景描述

阿里云服务器产生反弹shell告警，在短信收到同步信息。控制台显示有详细的反弹代码内容，包括进程路径、进程链。攻击IP关联样本有CS木马。

### 风险评估

- **服务器被控**：攻击者通过反弹shell获得服务器控制权
- **数据泄露**：可能被窃取敏感数据
- **横向渗透**：可能作为跳板进行内网渗透

---

## 2. 事件分析 (Event Analysis)

### 排查步骤

#### 1. 查看网络连接信息

```bash
netstat -anp|grep 8888
ps -aux |grep 8888
```

发现异常连接，端口8888的反弹shell进程。

#### 2. 系统计划任务查看

```bash
crontab -l
```

发现计划任务，删除后发现网络连接仍存在，说明存在隐藏计划任务。

#### 3. 追溯攻击来源

通过查询系统历史操作命令：
```bash
history | grep "8888"
```

发现通过echo命令写入反弹shell命令到 `/ron/root` 路径，写入日期为2024年7月var/spool/c31日。

#### 4. 全盘搜索恶意文件

```bash
grep -r "103.x.x.x" /etc/ /root/ /home/ 2>/dev/null

# 在 /root/.bash_history【历史记录】发现攻击痕迹
# 在 /etc/cron.d/test 路径发现反弹代码写入

# 在 /etc/profile.d/ 路径发现 1.sh 脚本
```

**最终发现的隐藏位置**：
- `/var/spool/cron/root` - 计划任务
- `/etc/cron.d/test` - 定时任务
- `/etc/profile.d/1.sh` - 开机启动脚本

---

## 3. 事件处置 (Incident Response)

### 处置措施

1. **云防火墙限制**
   - 对反弹端口进行限制
   - 对反弹shell IP进行黑名单处置

2. **安全基线加固**
   - 修改SSH登录密码

3. **终端防护**
   - 安装安全防护软件

4. **定期巡检**
   - 定期巡检终端系统

---

## 4. 事件思考 (Event Reflection)

### 经验总结

1. **最小化原则**
   - 互联网资产风险无处不在
   - 对外的暴露大大增加了被攻击的风险
   - 最小化原则非常重要

2. **应急处置要点**
   - 终端的应急处置是一个需要耐心、细心、决心的过程
   - 需要彻底清除所有隐藏的恶意文件

3. **安全产品防护**
   - 安全产品 WAF、IDS、IPS 等检测系统，可以阻断该攻击行为

4. **攻击手法特点**
   - 该反弹代码在**隐藏性、持久性、多样性**都有体现
   - 安全运营本质就是不断持续对抗

## 5. 技术细节 (Technical Details)

### 常见反弹shell检测点

| 检测位置 | 说明 |
|----------|------|
| `/var/spool/cron/` | 用户定时任务 |
| `/etc/cron.d/` | 系统定时任务 |
| `/etc/profile.d/` | 环境变量配置（开机启动） |
| `~/.bash_history` | 历史命令记录 |
| `/etc/rc.local` | 开机启动脚本 |
| `/etc/init.d/` | 系统服务脚本 |

### 排查命令汇总

```bash
# 网络连接
netstat -anp | grep -E "LISTEN|ESTABLISHED"

# 进程检查
ps -aux | grep suspicious

# 计划任务
crontab -l
ls -la /etc/cron.d/
ls -la /etc/profile.d/

# 全盘搜索
grep -r "恶意IP" /etc/ /root/ /home/

# 历史命令
history
```

## 6. 防御建议 (Defense Recommendations)

### 预防措施

| 措施 | 说明 |
|------|------|
| 最小化暴露面 | 关闭不必要的端口和服务 |
| 强密码策略 | 使用复杂密码，定期更换 |
| SSH密钥登录 | 禁用密码登录 |
| 安全产品 | 部署 WAF、IDS、IPS |
| 定期审计 | 定期检查日志和系统状态 |
| 及时更新 | 更新系统安全补丁 |

### 应急响应流程

```
1. 确认告警
2. 隔离受影响主机
3. 分析攻击路径
4. 清除恶意文件
5. 加固系统
6. 持续监控
7. 总结复盘
```
