# 防溯源追踪：隐藏真实IP与代理池搭建全攻略

## 1. 问题现状 (Current Status & Problem Analysis)

### 背景描述

在网络安全防护、渗透测试与攻防演练中，对目标主机进行扫描、探测时，经常会遭遇 WAF（Web 应用防火墙）拦截与 IP 封禁。一旦本机 IP 被封，就只能等待解封，严重影响测试进度。

### 风险评估

- **IP 被封**：导致测试中断，等待解封周期长
- **真实 IP 暴露**：即使使用代理，WebRTC/STUN 协议仍可能泄露本机公网 IP
- **身份溯源风险**：攻击行为可被追溯到真实来源

### 影响范围

- 渗透测试人员
- 红队攻防演练参与者
- 安全研究人员的资产扫描活动

---

## 2. 解决思路与方案对比 (Solution Options & Analysis)

### 核心原理

代理服务器的核心原理是 **流量中转**：所有访问请求先经过代理 IP 转发，再到达目标站点；目标站点看到的访问 IP 仅为代理 IP，而非你的真实出口 IP，从而实现身份隐藏与溯源防护。

### 协议类型对比

| 协议类型 | 支持范围 | 速度 | 安全性 | 适用场景 |
|----------|----------|------|--------|----------|
| HTTP 代理 | 仅网页协议 | 快 | 一般 | 简单爬虫、基础访问 |
| HTTPS 代理 | HTTP 加密版 | 中 | 较高 | 安全网页访问 |
| SOCKS5 代理 | 全协议 | 略慢 | 高 | 攻防演练、全局代理 |

### 代理获取方案

| 方案 | 成本 | 稳定性 | 延迟 | 适用场景 |
|------|------|--------|------|----------|
| 免费代理池 | 免费 | 低 | 高 | 临时测试、简单任务 |
| 付费代理池 | 付费 | 高 | 低 | 正式渗透、长期项目 |

## 3. 最佳实践框架 (Best Practice Framework)

### 推荐方案

**付费代理池 + WebRTC 防护插件** 是最佳实践，可靠稳定且能彻底隐藏真实 IP。

### 关键工具

1. **ProxyCat-V2.0.4** — 付费代理池管理工具
   - GitHub: https://github.com/honmashironeko/Proxycat/tree/main
2. **无影工具·轻武器库** — 免费代理池爬取
3. **WebRTC Leak Shield** — 浏览器 WebRTC 泄露防护插件

### 架构设计

```
[本机真实IP] 
    ↓ 流量
[代理客户端] → [代理池轮换] → [代理IP] → [目标站点]
                    ↑
              ProxyCat 管理
```

## 4. 具体操作步骤 (Implementation Steps)

### 步骤一：免费代理池获取（无影工具）

1. 使用无影工具·轻武器库的代理池自动爬取功能
2. 设置搜索引擎的 key 以获取免费代理
3. 点击启用代理，配置代理池接口
4. 配置成功后，使用浏览器代理验证

> 注意：延时较高，仅适合临时测试

### 步骤二：付费代理池搭建（ProxyCat）

1. 下载 ProxyCat-V2.0.4
```bash
git clone https://github.com/honmashironeko/Proxycat.git
cd Proxycat
pip install -r requirements.txt
```

2. 配置 `config.ini` 配置文件

3. 启动服务
```bash
python proxycat.py
```

4. 浏览器开启代理，访问 IP 查询网站验证

### 步骤三：彻底隐藏真实 IP（WebRTC 防护）

**问题根源**：即使挂了代理，WebRTC、STUN 协议仍可能泄露本机公网 IP

**解决方案**：安装 **WebRTC Leak Shield** 浏览器插件

1. 安装 WebRTC Leak Shield 浏览器插件
2. 关闭浏览器 WebRTC 功能
3. 阻止 STUN 协议向外发送真实 IP
4. 启用插件后重新检测 IP 泄露

**验证方法**：通过在线 IP 泄露检测工具确认真实 IP 已被完全屏蔽，仅显示代理 IP。
