# 前端加密测不动？全局热加载帮你自动接管签名流程

> 来源：微信公众号 - Yak Project
> 日期：2026-03-18
> 标签：#前端安全 #YAK #加密测试 #热加载

## 概述

本文介绍了如何使用 YAK 的**全局热加载（Global Hotpatch）**功能，自动完成前端加密接口的签名流程，解决手动测试加密接口时的繁琐操作。

## 靶场环境

- **Vulinbox 靶场**：http://127.0.0.1:18080/
- **API 文档**：http://127.0.0.1:18080/crypto/challenge-api-docs
- **Challenge 接口**：http://127.0.0.1:18080/api/get-challenge
- **受保护接口**：http://127.0.0.1:18080/api/user/info

## 加密流程分析

该靶场的交互流程包含**两段必须执行的逻辑**：

1. **请求前**：自动获取 challenge 并生成签名
2. **响应后**：自动解密受保护接口的返回数据

### 完整交互流程

```
1. 请求 /api/get-challenge → 获取加密的 challenge 和 iv
2. 客户端解密 challenge 得到 nonce
3. 使用 nonce + HMAC Key 计算签名
4. 请求 /api/user/info 时携带签名到 X-Auth-Signature 头
5. 服务端返回 AES-CBC 加密的业务数据
```

## 全局热加载实现

### 核心函数

#### 1. 获取 Challenge 并计算签名

```go
fetchChallengeSignature = func(isHttps, packet) {
    host = poc.GetHTTPPacketHeader(packet, "Host")
    
    // 构造 challenge 请求
    challengeReq = "GET /api/get-challenge HTTP/1.1\r\n" +
                   "Host: " + host + "\r\n\r\n"
    
    challengeRsp, _ = poc.HTTP(challengeReq, poc.https(isHttps))
    
    // 解析并解密
    params = json.loads(poc.GetHTTPPacketBody(challengeRsp))
    nonce = codec.AESCBCDecrypt(API_AES_KEY, 
                                 codec.DecodeBase64(params.challenge),
                                 codec.DecodeBase64(params.iv))
    
    return codec.EncodeToHex(codec.HmacSha256(API_SIGN_KEY, nonce))
}
```

#### 2. 解密响应

```go
decryptProtectedResponse = func(packet) {
    params = json.loads(poc.GetHTTPPacketBody(packet))
    plain = codec.AESCBCDecrypt(API_AES_KEY,
                                 codec.DecodeBase64(params.data),
                                 codec.DecodeBase64(params.iv))
    return poc.ReplaceHTTPPacketBody(packet, plain)
}
```

### Hook 挂载点

#### 1. beforeRequest - 自动补签名

```go
beforeRequest = func(isHttps, originReq, req) {
    if !isTargetRequest(isHttps, req) {
        return req
    }
    signature = fetchChallengeSignature(isHttps, req)
    req = poc.ReplaceHTTPPacketHeader(req, "X-Auth-Signature", signature)
    return req
}
```

#### 2. afterRequest - 按需解密响应

```go
afterRequest = func(isHttps, originReq, req, originRsp, rsp) {
    if !isTargetRequest(isHttps, req) {
        return rsp
    }
    // 只有带 X-Yak-Force-Plaintext: 1 才解密
    if poc.GetHTTPPacketHeader(req, "X-Yak-Force-Plaintext") != "1" {
        return rsp
    }
    return decryptProtectedResponse(rsp)
}
```

#### 3. hijackSaveHTTPFlow - MITM 存库明文化

```go
hijackSaveHTTPFlow = func(flow, modify, drop) {
    req = codec.StrconvUnquote(flow.Request)
    if !isTargetRequest(false, req) && !isTargetRequest(true, req) {
        modify(flow)
        return
    }
    rsp = codec.StrconvUnquote(flow.Response)
    flow.Response = codec.StrconvQuote(string(decryptProtectedResponse(rsp)))
    modify(flow)
}
```

## 使用场景

### 场景1：Web Fuzzer 直接发明文

```http
GET /api/user/info HTTP/1.1
Host: 127.0.0.1:18080
X-Yak-Force-Plaintext: 1
```

自动完成：
- 自动补上 X-Auth-Signature
- 自动解密响应为明文

### 场景2：MITM 保留在线协议，存库明文

- 浏览器收到的仍是原始密文（不影响前端逻辑）
- MITM 数据库中保存的是解密后的明文（便于分析）

## 全局热加载 vs 模块热加载

| 特性 | 全局热加载 | 模块热加载 |
|------|-----------|-----------|
| 作用范围 | 全局所有请求 | 单个模块 |
| 执行顺序 | 先执行（全局 → 模块） | 后执行 |
| 适用场景 | 协议层（加解密） | 业务逻辑 |

## 总结

全局热加载的核心价值：
1. **自动化**：无需手动获取 challenge 和计算签名
2. **透明化**：测试时无需关心底层加密细节
3. **不破坏协议**：MITM 模式下保持在线流量完整性
4. **职责分离**：协议层（加密）由全局处理，业务逻辑由模块处理

> 适用于复杂场景：加密 + SQL 注入测试等组合漏洞挖掘
