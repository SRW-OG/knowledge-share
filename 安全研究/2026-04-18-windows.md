# Windows 痕迹清理与蓝队溯源反制

## 一、问题现状 (Current Status & Problem Analysis)

### 背景描述

Windows 系统的日志与痕迹记录体系，是蓝队还原攻击路径、溯源攻击行为的关键依据。很多渗透测试人员在获取目标权限后，仅做简单的日志清空操作，不仅容易触发系统告警，还会因为遗漏专项痕迹被蓝队完整溯源。

### 影响范围

- **事件日志**：安全日志、系统日志、应用程序日志
- **命令执行痕迹**：PowerShell 历史记录、CMD 历史
- **远程登录记录**：RDP 登录痕迹、注册表项、凭据缓存
- **文件操作痕迹**：时间戳属性、Prefetch 预读取、临时文件
- **系统专项日志**：PowerShell 脚本块日志、转录日志、防火墙日志

### 风险评估

1. **直接删除 `.evtx` 文件** → 日志服务异常，触发系统告警
2. **批量清空所有日志** → 触发 SOC 平台高优先级告警
3. **遗漏 PowerShell 专项日志** → 攻击路径被完整溯源
4. **文件时间戳异常** → 蓝队按时间排序快速定位异常文件

## 二、解决思路与方案对比 (Solution Options & Analysis)

### 方案对比表

| 方案 | 核心工具 | 隐蔽性 | 操作复杂度 | 蓝队检测难度 |
|------|---------|--------|-----------|-------------|
| 直接删除 `.evtx` 文件 | 文件管理器 | ⭐（极易告警） | 低 | 极低 |
| 停止日志服务后删除 | sc / 文件操作 | ⭐⭐ | 中 | 低 |
| `wevtutil` 精准清理 | wevtutil | ⭐⭐⭐⭐ | 中 | 高 |
| `wevtutil` 批量清空 | wevtutil | ⭐⭐ | 低 | 中 |
| 时间戳伪造 | PowerShell | ⭐⭐⭐ | 中 | 高 |

### 关键结论

**最佳方案**：`wevtutil` 精准清理 + 系统原生工具链配合

**理由**：
- 通过官方 API 清理日志，不破坏日志文件结构
- 支持按条件筛选，仅删除攻击相关条目
- 使用系统原生工具，避免第三方工具痕迹

## 三、最佳实践框架 (Best Practice Framework)

### 3.1 核心原则

> 痕迹清理的最优解，不是事后擦除，而是从攻击开始就尽量不留下痕迹。

### 3.2 反溯源通用技巧

1. **多层跳板代理**：至少通过 3 层以上跳板机发起连接，隐藏真实 IP
2. **操作无痕化**：优先使用内存执行（无文件 PowerShell 攻击），避免写入硬盘
3. **流量伪装**：使用 443 端口 TLS 加密传输，伪装为正常 HTTPS 流量
4. **时间混淆**：选择目标业务低峰期操作，操作间隔随机化
5. **工具原生适配**：优先使用系统自带工具（wevtutil、powershell、sc、reg）

### 3.3 系统权限要求

> ⚠️ **重要**：安全日志、系统日志的清理操作，必须拥有 **System 权限** 才能完整执行。

获取 System 权限的快速方法（创建临时服务）：
```cmd
sc create temp_syscmd binpath= "cmd.exe /k calc" type= own type= interact
sc start temp_syscmd
```
