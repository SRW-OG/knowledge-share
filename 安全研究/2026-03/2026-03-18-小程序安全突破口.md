## 概述

本文详细介绍了小程序的生态现状、核心安全突破点（含源码获取、CMRF 漏洞、特有 API 漏洞）及第三方相关风险，为安全测试与防护提供了关键参考。

## 一、小程序生态与基础应用

### 1.1 生态现状

**主流平台**：
- 微信、支付宝、百度 APP、字节跳动系（抖音/今日头条）、京东、QQ 浏览器
- 覆盖防疫健康码、文件分享、金融服务等场景

**火爆核心原因**：
1. 强大平台依托（微信/支付宝用户基数大）
2. 轻量便捷（无需安装，即开即用）
3. 行业重视（大厂持续投入发展）

### 1.2 资产与信息搜集

**核心目标**：获取小程序子域名、主体信息、开发者信息等资产

**实操工具**：ThorSRC 相关 Python 脚本
- `get-domains.py` - 获取域名
- `get-miniapps.py` - 获取小程序信息

**关键参数**：
- 小程序 ID
- X-WECHAT-KEY
- Cookie 信息

**输出结果**：
- 目标小程序关联的域名（如百度系小程序关联 18 个域名）
- 小程序名称及对应 ID

## 二、小程序源码获取

### 2.1 存储路径

| 平台 | 存储路径 |
|------|----------|
| 安卓（微信） | `/data/data/com.tencent.mm/MicroMsg/{用户 ID}/appbrand/pkg/` |
| IOS（微信） | `/var/mobile/Containers/Data/Application/{程序 UUID}/Library/WechatPrivate/{用户 ID}/WeApp/LocalCache/release/{小程序 ID}/` |
| 支付宝 | `/Documents/NAMAPP_UNZIP/{随机 ID}/` |

### 2.2 文件格式与解析

**微信小程序**：
- 核心文件：`.wxapkg`
- 头部固定标识：`0xBE`
- 尾部固定标识：`0xED`
- 包含索引段长度、数据段长度等校验信息

**支付宝小程序**：
- 未加密压缩包
- 包含 `SIGN.json`、`Manifest.xml`、`CERT.json` 等配置文件

### 2.3 解析后核心文件

| 文件类型 | 微信 | 支付宝 | 说明 |
|----------|------|--------|------|
| 配置类 | `app.json` | - | 定义页面路径、窗口样式 |
| 配置类 | `app-config.json` | - | 应用配置 |
| 样式类 | `.wxss` | `.acss` | 样式文件（注意组件选择器限制） |
| 页面类 | `.wxml` | `.axml` | 页面结构描述 |
| 逻辑类 | `app.js` | - | 核心交互逻辑 |
| 逻辑类 | `page-frame.html` | - | 页面框架 |

## 三、CMRF 漏洞（跨小程序请求伪造）

### 3.1 漏洞定义

利用小程序对用户在平台内身份的信任，结合用户已登录的身份信息，向小程序后端发送恶意数据包，使用户无意识完成危害操作。

### 3.2 利用流程

```
1. 构造恶意分享内容 → 包含目标页面路径 + 恶意参数
2. 诱导用户点击 → 通过社交分享（微信聊天、朋友圈）
3. 执行危害操作 → 小程序后端基于登录态执行请求
```

### 3.3 典型案例

**雷神商城密码修改漏洞**：
- 构造含 `newpwd=Abc123` 参数的分享链接
- 诱导用户点击后完成密码篡改

## 四、小程序特有 API 漏洞

### 4.1 敏感数据传输逻辑

小程序通过 API 获取用户敏感信息（手机号、用户信息）时，采用 **"数据 + 签名 + 密文串"** 的传输方式：

```
开发者服务器 → session_key 校验签名合法性 → 返回敏感数据
```

### 4.2 核心风险点

| 风险点 | 描述 |
|--------|------|
| 缺少 session_key 校验 | 攻击者可绕过身份验证 |
| 签名校验不完善 | 攻击者可伪造签名解密敏感数据 |
| 密钥泄露 | 导致签名算法被破解 |

### 4.3 各平台差异

- **微信**：敏感数据加密算法、校验流程
- **支付宝**：类似的签名+密钥双重验证
- **字节跳动**：平台特定的校验机制

## 五、第三方相关安全风险

### 5.1 第三方类型

| 类型 | 示例 |
|------|------|
| 一键生成平台 | 快速搭建小程序 |
| 后台管理平台 | 微擎 (www.w7.cc) |
| 小程序插件 | 营销插件、门店插件 |
| 开发 SDK | 第三方开发库 |
| 账户授权服务 | OAuth 授权服务 |

### 5.2 风险特征

1. **数量庞大**：第三方工具/插件种类繁多
2. **安全隐患**：代码漏洞、权限管理松散
3. **测试覆盖难**：第三方代码难以全面审计

### 5.3 典型案例

**微擎 (www.w7.cc)**：
- 开源微信公众平台管理系统
- 被多个小程序后台采用
- 插件更新频繁（如多商户入驻万能门店 1.0.4 版本 1 周内更新 2 次）
- 可能引入未知风险

## 七、关键问题总结

### Q1：小程序源码的核心存储路径的平台差异是什么？

**答案**：

| 平台 | 核心存储路径 |
|------|--------------|
| 安卓微信 | `/data/data/com.tencent.mm/MicroMsg/{用户 ID}/appbrand/pkg/` |
| IOS 微信 | `/var/mobile/Containers/Data/Application/{程序 UUID}/Library/WechatPrivate/{用户 ID}/WeApp/LocalCache/release/{小程序 ID}/` |
| 支付宝 | `/Documents/NAMAPP_UNZIP/{随机 ID}/` |

**解析流程**：
- **微信小程序**：提取 `.wxapkg` 文件（头部 `0xBE`、尾部 `0xED`），解压后得到 `app.js`、`.wxss`、`.wxml` 等
- **支付宝小程序**：直接获取未加密压缩包，解压后得到 `SIGN.json`、`Manifest.xml` 等

### Q2：CMRF 漏洞的核心利用原理是什么？

**答案**：

**核心原理**：利用小程序对用户在平台（微信、支付宝）的身份信任，构造包含恶意参数的小程序页面链接，当用户点击时自动携带登录态执行危害请求。

**完整攻击链路**：
1. **Step 1 构造恶意链接** - 拼接目标小程序页面路径 + 恶意参数
2. **Step 2 诱导传播** - 通过社交分享传递恶意链接
3. **Step 3 触发执行** - 用户点击后自动发送请求
4. **Step 4 完成攻击** - 后端执行恶意操作并返回结果

### Q3：小程序第三方生态存在哪些核心安全风险？

**答案**：

**核心安全风险**：
1. 第三方平台/插件自身存在漏洞（代码逻辑缺陷、权限管控不严）
2. 一键生成工具代码标准化，存在通用漏洞
3. 第三方 SDK/插件授权过度，泄露敏感数据

**难以防控的原因**：
1. 第三方类型繁杂，数量庞大（仅微擎就有上千种模块）
2. 第三方工具更新频繁（新内容可能引入风险）
3. 授权关系复杂，开发者安全校验不足

---

## 总结

小程序安全测试的核心突破口：

1. **源码获取**：通过安卓存储路径或抓包获取 `.wxapkg` 文件
2. **CMRF 漏洞**：利用登录态信任构造恶意请求
3. **API 漏洞**：绕过签名校验获取敏感数据
4. **第三方风险**：关注第三方平台和插件的安全问题
