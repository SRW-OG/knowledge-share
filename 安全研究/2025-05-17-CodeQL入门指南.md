# CodeQL入门指南

## 1. 问题现状

### 背景描述

CodeQL 是 GitHub 推出的一种**代码分析引擎和查询语言**，用于查找软件中的漏洞和安全问题。其核心理念是将代码表示成一种可以查询的数据库结构，开发者或研究人员可以像查询数据库一样查询代码的结构和行为。简单来说，CodeQL 是一种可以通过编写 **QL** 制定规则的静态分析工具（SAST）。

### 技术定位

- **分析层级**：CodeQL 在 **AST（抽象语法树）层** 做污点传播
- **工作模式**：编译源码 → 生成数据库 → QL 查询
- **数据流追踪**：支持本地数据流和全局数据流两种模式

### 竞品对比

| 工具 | 分析层级 | 污点追踪 | 开源程度 | 适用场景 |
|------|---------|---------|---------|---------|
| **CodeQL** | AST | ✅ 全局污点追踪 | 引擎闭源，SDK开源 | 多语言安全审计 |
| **Soot** | IR (Jimple) | ✅ 完整实现 | 全开源 | Java/Android分析 |
| **Tai-e** | IR (Soot-based) | ✅ 插件化设计 | 全开源 | 学术研究与教学 |
| **Semgrep** | AST + 模式匹配 | ⚠️ 有限支持 | 全开源 | 快速规则编写 |
| **Fortify** | 中间语言 | ✅ 商业实现 | 闭源 | 企业级代码审计 |

## 2. 解决思路与方案对比

### 核心架构

CodeQL 的漏洞扫描分为两部分：

```
源码 → AST数据库创建 → QL规则查询 → 漏洞报告
         ↓                    ↓
   codeql database create   codeql query
```

### 环境搭建方案

#### 方案A：完整手动安装（推荐）

```bash
# 1. 下载引擎
wget https://github.com/github/codeql-cli-binaries/releases/latest/download/codeql-linux64.zip
unzip codeql-linux64.zip

# 2. 配置环境变量
export PATH=$PATH:/path/to/codeql

# 3. 克隆SDK
git clone https://github.com/github/codeql
mv codeql ql

# 4. VSCode安装 CodeQL插件
# 添加可执行文件路径：CodeQL > Executable Path
```

#### 方案B：使用官方CLI

```bash
# 一键创建数据库（以Java为例）
codeql database create <db-name> --language=java --source-root=<src-path>

# 执行查询
codeql database analyze <db-name> <ql-file> --format=sarif-latest --output=results.sarif
```

### 优缺点对比

| 方案 | 优点 | 缺点 |
|------|------|------|
| **手动安装** | 完全可控，可自定义规则 | 配置复杂 |
| **VSCode插件** | 交互友好，可视化调试 | 不适合自动化批量扫描 |

## 3. 最佳实践框架

### QL查询语法体系

#### 基础语法结构

```ql
from [datatype] var
where condition(var = something)
select var
```

#### 示例：查找所有值为1的int字面量

```ql
import java

from int i
where i = 1
select i
```

### 核心类库

| 类 | 作用 | 示例 |
|----|------|------|
| **Method** | 所有方法 | `Method method` 获取项目中所有方法 |
| **MethodCall** | 方法调用 | `MethodCall call` 获取所有方法调用 |
| **Parameter** | 参数 | `Parameter p` 获取所有参数 |
| **DataFlow::Node** | 数据流节点 | 表示数据流中的某个位置 |

#### 示例：查找名为getStudent的方法

```ql
import java

from Method method
where method.hasName("getStudent")
select method.getName(), method.getDeclaringType()
```

### 谓词（Predicate）封装

当where条件复杂时，用谓词封装：

```ql
import java

predicate isStudent(Method method){
    exists(|method.hasName("getStudent"))
}

from Method method
where isStudent(method)
select method.getName(), method.getDeclaringType().getName()
```

## 4. 具体操作步骤

### Step 1：创建分析数据库

```bash
# Java项目
codeql database create codeqltest --language=java

# Python项目
codeql database create codeqltest --language=python

# JavaScript/TypeScript
codeql database create codeqltest --language=javascript
```

### Step 2：定义Source（污点源）

```ql
import java
import semmle.code.java.dataflow.FlowSources

predicate isSource(DataFlow::Node src) {
    src instanceof RemoteFlowSource
}

from DataFlow::Node src
where isSource(src)
select src, "是一个Source点"
```

### Step 3：定义Sink（危险汇点）

```ql
predicate isSink(DataFlow::Node sink) {
    exists(Method method, MethodCall call |
        method.hasName("query") and
        call.getMethod() = method and
        sink.asExpr() = call.getArgument(0)
    )
}
```

### Step 4：配置全局数据流

```ql
import java
import semmle.code.java.dataflow.DataFlow
import semmle.code.java.dataflow.FlowSources

module SourceToSinkConfig implements DataFlow::ConfigSig {
    predicate isSource(DataFlow::Node source) {
        source instanceof RemoteFlowSource
    }

    predicate isSink(DataFlow::Node sink) {
        exists(Method method, MethodCall call |
            method.hasName("query") and
            call.getMethod() = method and
            sink.asExpr() = call.getArgument(0)
        )
    }
}

module SourceToSink = TaintTracking::Global<SourceToSinkConfig>;

from DataFlow::Node source, DataFlow::Node sink
where SourceToSink::flow(source, sink)
select source, "flow to", sink
```

### Step 5：添加Sanitizer（净化/过滤）

```ql
predicate isBarrier(DataFlow::Node sanitizer) {
    sanitizer.getType() instanceof PrimitiveType
    or sanitizer.getType() instanceof BoxedType
    or sanitizer.getType() instanceof NumberType
    or exists(ParameterizedType pt |
        sanitizer.getType() = pt and pt.getTypeArgument(0) instanceof NumberType
    )
}
```

## 5. 总结与建议

### 核心要点

1. **CodeQL在AST层做分析**，而非IR层——这意味着它更依赖词法/语法解析，对复杂控制流的建模能力有限
2. **全局数据流**比本地数据流更强大，但精确度和性能较低
3. **污点追踪（TaintTracking）**是检测漏洞的核心模块
4. **Sanitizer的编写质量**直接决定误报率

### 进阶学习路径

```
入门 → QL语法 → Source/Sink定义 → 数据流配置
  ↓
进阶 → 污点追踪优化 → sanitizer设计 → 自定义规则开发
  ↓
深入 → CodeQL实现原理 → AST vs IR对比 → 污点追踪算法
```

## 附录：相关SAST工具补充

### Soot — Java静态分析利器

**Soot** 是一个开源的Java静态分析框架，由University of British Columbia开发。它将Java字节码转换为中间表示（IR）进行高级分析。

#### 核心特性

- **多层次IR**：Baf（精简字节码）→ Jimple（类型化3地址码）→ Grimp（聚合指令）
- **强大的污点追踪**：通过`SourceLocator`和`SinkRecorder`配置
- **Dava工具**：可将分析结果反编译回Java源码

#### Jimple 3地址码示例

```java
// Java源码
int result = a + b + c;

// Jimple IR（Soot中间表示）
$r0 = a;
$r1 = b;
$r2 = c;
$r3 = $r0 + $r1;
$result = $r3 + $r2;
```

**Tai-e** 是一个新生的Java静态分析教学框架，由华中科技大学开发，代码结构清晰，适合学术研究。

### 污点分析核心概念图解

```
[Source] → 不可信输入 → [污点传播] → [Sink] → 漏洞触发
              ↓              ↓
         [Sanitizer]    [Barrier/过滤]
              ↓              ↓
         净化/过滤     阻断传播路径
```

#### 常见Source示例

| 语言 | Source | 危险程度 |
|------|--------|---------|
| Java | `request.getParameter()` | 高 |
| Java | `System.getenv()` | 中 |
| Python | `os.environ['USER_INPUT']` | 高 |
| JS | `document.cookie` | 中 |
| C | `scanf()`, `gets()` | 高 |

#### 常见Sink示例

| 语言 | Sink | 漏洞类型 |
|------|------|---------|
| Java | `SQLConnection.prepareStatement()` | SQL注入 |
| Java | `Runtime.exec()` | 命令注入 |
| Python | `eval()`, `exec()` | 代码注入 |
| JS | `innerHTML` | XSS |
| C | `strcpy()`, `sprintf()` | 缓冲区溢出 |

### 静态分析关键技术对比

| 技术 | 说明 | 精度 | 性能 | 适用场景 |
|------|------|------|------|---------|
| **数据流分析** | 追踪数据从Source到Sink的传播路径 | ⭐⭐⭐ | ⭐⭐⭐ | 污点追踪、信息流 |
| **控制流分析** | 分析程序执行路径和循环结构 | ⭐⭐⭐ | ⭐⭐⭐⭐ | 路径可达性分析 |

| **符号执行** | 用符号代替具体值执行程序 | ⭐⭐⭐⭐ | ⭐⭐ | 路径探索 |

### CodeQL vs 传统SAST工具链

```
传统SAST:
  源码 → 编译器前端 → AST → 语义分析 → 规则引擎 → 报告
           (clang/soot)                                 
           ↓                                          
        CodeQL: AST存储在数据库中，用QL查询语言检索
           ↓                                          
        优势: 查询逻辑与分析引擎分离，可自定义规则
        劣势: AST层信息损失，跨函数分析能力受限
```

**关键洞察**：CodeQL选择在AST层做分析是一种工程权衡——牺牲部分精度换取查询灵活性和跨语言统一体验。真正的生产级污点分析（如Fortify、Checkmarx）通常会在更底层的IR或字节码层实现。
