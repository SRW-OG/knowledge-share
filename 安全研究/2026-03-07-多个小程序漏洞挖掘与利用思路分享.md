## 二、漏洞详情

### 2.1 低价享受高价（支付逻辑漏洞）

#### 测试思路

1. 锁定一个购票小程序
2. 购买出行船票或车票，选择目的地，下单记录数据包

#### 发现过程

1. 发现创建订单接口 `shipgateway/shipOrderApi/createOrder`
2. **关键发现**：没有 `sign` 校验字段，存在问题的可能性较大
3. 使用 Burp Suite 重发器进行修改测试

#### 漏洞利用

**第一步：修改乘客类型**

- 修改 `passengerType` 字段：
  - `1` = 成人（票价 100）
  - `2` = 儿童（票价 50）
  - `3` = 长者（票价 50）

- 单独修改 `passengerType` 会提示"价格不匹配"
- 需要同时修改 `passengerType` 和 `ticketPrice` 两个字段

```json
{
  "passengerType": 2,
  "ticketPrice": 50
}
```

**第二步：修改舱位等级**

- 修改 `seatId` 字段：
  - `seatId: 1` = 普通舱
  - `seatId: 0` = 头等舱

- 在中等舱数据包中修改 `seatId` 为头等舱，订单创建成功但舱位类型还是中等舱，价格却变成了头等舱价格

**第三步：组合利用**

- 生成高等舱的订单
- 将用户类型、票价、舱位三个字段都修改为最低层面
- 成功创建高等舱位的低价订单

```json
{
  "seatId": 0,
  "passengerType": 2,
  "ticketPrice": 50
}
```

**漏洞根因**：后端只校验了决定价格字段和类型字段间是否一一对应，对当前舱位字段没有限制。

### 2.2 0元购思路

#### 漏洞背景

有的船票存在携童免费措施，通过伪造身份实现 0 元购票。

#### 测试过程

1. 添加正常乘客信息绕过验证
2. 找到添加乘客的数据包，修改身份证和日期为儿童的
3. 在下单时把身份证修改回来（使用自己的身份证）
4. 选择免费票（儿童免费票不能独立购买，需要携带一名成人）

#### 最终利用

- 一份钱买两个成人的票
- 0 元上船

**注意**：虽然可以支付订单，但后续会自动退票，或有人工客服打电话审核。

### 2.3 越权查看订单信息

#### 发现过程

1. 生成订单后出现订单号
2. 查询订单的接口会回显当前订单的乘客信息三要素
3. 经过大小号替换订单号测试，可以越权查询到他人的订单信息要素

#### 关键发现

订单查询接口返回了额外的敏感字段：

```json
{
  "openId": "xxxxx",
  "unionId": "xxxxx"
}
```

#### 漏洞危害

- 这两个字段都是**鉴权字段**
- 有了此字段可以跟替换 Cookie 一样替换别人身份
- 操作此小程序所有增删改查功能点

**遗憾的是**：虽然开着 Hae（安全工具），但并没有相关的规则字段正则匹配到这个点。订单号无法遍历，其他功能点没有找到出现订单号的地方。

## 三、挖掘思路总结

### 3.1 测试支付漏洞技巧

| 步骤 | 操作 |
|------|------|
| 1 | 搜索数据包中的 `price` 字段 |
| 2 | 将每个字段都改变为最小的数字，逐一发包测试 |
| 3 | 观察哪个字段可以影响订单的生成 |
| 4 | 分析字段间的逻辑关系 |

### 3.2 关键点

1. **没有 sign 校验**：接口可能存在安全问题
2. **字段间逻辑**：注意 `passengerType` 和 `ticketPrice` 的对应关系
3. **响应包分析**：不经意响应包可能带出其他信息（如 openId、unionId）
4. **组合测试**：多字段组合尝试绕过

### 3.3 挖掘建议

1. **细心发现**：即使开着安全工具，也可能遗漏敏感信息
2. **举一反三**：一个接口可能引出另一种思考
3. **关注响应包**：不只看输出，还要看响应中的隐藏字段
