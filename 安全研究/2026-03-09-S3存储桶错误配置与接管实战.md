# 【云安全专题-4】S3 存储桶错误配置与接管实战

## 1. 问题现状 (Current Status & Problem Analysis)

### 背景描述

在云安全的江湖里，S3（Simple Storage Service）就像是少林寺的藏经阁。它虽然名字里带有 "Simple"，但其权限配置的复杂程度，足以让许多资深运维阴沟里翻船。

据统计，云上数据泄露事件中，**超过 60% 源于 S3 存储桶的配置错误**。从 Capital One 的亿级数据失窃，到无数初创公司源代码的"裸奔"，S3 始终是红队攻击者最喜欢的突破口。

### 风险评估

- **数据泄露**：敏感文件暴露在公网
- **未授权访问**：攻击者可直接读取/下载文件
- **权限接管**：配置错误可导致存储桶接管

### 影响范围

- AWS S3
- 阿里云 OSS
- 腾讯云 COS
- 华为云 OBS

## 4. 具体操作步骤 (Implementation Steps)

### 4.1 侦察阶段：发现目标存储桶

#### 被动搜集：利用搜索引擎

**Google Dorks**：
```
site:s3.amazonaws.com "password"
site:s3.amazonaws.com "config"
site:s3.amazonaws.com "backup"
site:s3.amazonaws.com inurl:admin
```

**GrayhatWarfare**：
- 专门爬取公开 S3 桶的搜索引擎
- 可搜索 `id_rsa`、`shadow`、`wallet` 等关键词

> 红队技巧：搜索目标公司的域名关键词，往往能发现废弃的测试桶。

#### 主动枚举：Bucket 爆破

**命名规则**：`[公司]-[环境]-[用途]`
- `corp-dev`、`corp-backup`、`corp-logs`、`corp-internal`

**工具推荐**：
- `fuzz_bucket`：基于字典快速碰撞
- `CloudEnum`：不仅扫 AWS，还能扫 Azure 和 GCP

**判断依据**：
| 响应 | 含义 |
|------|------|
| `404 Not Found` | 桶不存在 |
| `403 Forbidden` | 桶存在，但没权限（好消息） |
| `200 OK` | 大奖！桶存在且允许列出内容 |

### 4.2 漏洞利用：权限配置错误

#### S3 权限控制类型

1. **ACL（旧式）**：访问控制列表
2. **Bucket Policy（新式）**：存储桶策略

#### 常见漏洞利用

**1. Bucket Object 遍历 (ListBucket)**
- 允许列出桶内所有对象
- 可获取敏感文件名和路径

**2. 未授权文件读取 (GetObject)**
- 直接读取桶内文件
- 包括备份、配置、密钥等

**3. 文件上传 (PutObject)**
- 上传恶意文件
- 网页挂马

**4. 存储桶接管**
- 桶配置错误时可能接管

## 5. 总结与建议 (Summary & Recommendations)

### 防御建议

| 措施 | 说明 |
|------|------|
| 最小权限原则 | 仅授予必要权限 |
| 禁用公共访问 | 关闭匿名访问 |
| 启用加密 | 服务端/客户端加密 |
| 日志审计 | 记录所有访问 |
| 定期检查 | 使用 cloudcustodian |

### 检查清单

- [ ] 禁用公共访问
- [ ] 启用 S3 Block Public Access
- [ ] 配置 Bucket Policy 严格限制
- [ ] 启用访问日志
- [ ] 定期审计权限配置
- [ ] 启用加密
- [ ] 配置生命周期策略
